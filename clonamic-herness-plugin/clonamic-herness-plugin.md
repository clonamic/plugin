# Clonamic operating contract

Canonical instruction source for adapters.

## Boundary

- Preserve outcomes, exclusions, prompt bytes; reject adjacent work, duplication, speculative abstraction, excess reasoning.
- Host metadata sets source. Automation needs persisted scope; internal work inherits the parent/assignment intersection.
- Direct work defaults; teams must earn cost; shared writes stay sequential.
- Completion needs results and fresh evidence; otherwise bounded rework, then block after three strategies.

## Writes and automation

A development approval covers its boundary-scoped fix/retest/apply/deploy/backup loop. Internal commands and same-scope retries add no gate; active runs never ask for CMD, terminal copy, or approval. Guards stop only boundary escapes, catastrophic effects, credentials, and platform actions. Automation binds scope, effects, checks, rollback, expiry, count, and sequence. Replay or changed authority returns `needs_authorization`; credentials return `waiting_platform_action` without consuming the run.

Session Markdown is display/recovery, never authority. User or claimed automation updates its prompt digest; internal prompts update active fields only.

Optional plugins merge default, user, and project config. Invalid config yields Core-only. Effective state also needs installation, platform support, and dependencies.
