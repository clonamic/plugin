# 전달 형태 카탈로그 (packaging-catalog)

패키징 전략가·환경 분석가·기술 위원회가 읽는다. 플랫폼 하나의 세부 한도는 플랫폼 프로필(`profiles/<name>.md`)에 있고, 이 파일은 **형태끼리 비교**하기 위한 일반 지식이다. 정책·심사 기간처럼 바뀌는 사실은 **확인 필요**로 적었다 — 근거로 쓰기 전에 확인하고, 확인하지 못하면 판단에 [추측]을 붙인다.

## 비교 기준 (점수 1~5, 높을수록 유리)

| 기준 | 무엇을 보나 |
|---|---|
| 도달 | 사용자가 처음 쓰기까지의 장벽(설치·가입·주소 기억) |
| 입력 | 글·버튼·사진·파일·음성·위치를 얼마나 자연스럽게 받나 |
| 출력 | 긴 글·표·그림·지도·달력을 보여 줄 수 있나 |
| 먼저 말 걸기 | 알림·리마인더를 보낼 수 있나, 조건·한도는 |
| 신원 | 사람을 어떻게 알아보나(채널 키, 로그인, 기기) |
| 오프라인 | 연결이 끊겨도 쓸 수 있나 |
| 심사·정책 | 스토어 심사, 채널 승인, 사업자 인증, 도메인 |
| 구현 시간 | 같은 기능을 배포까지 만드는 시간(상대값) |
| 운영 | 업데이트·호스팅·비용·담당자 |

## 형태별 특징

### 메신저 챗봇 (예: 카카오톡 채널 챗봇)
- 도달 5: 이미 깔린 앱, 채널 추가만. 비기술 사용자에게 가장 낮은 장벽.
- 입력: 글·버튼 중심. 사진·파일·위치는 플랫폼마다 다름(**확인 필요**, 프로필 참고).
- 출력: 짧은 글과 버튼이 강점. 표·긴 보고서·그림은 약함(마크다운 미렌더링, 말풍선·글자 한도).
- 먼저 말 걸기: 가능하지만 한도·조건이 있음(프로필 참고). 광고성 메시지 규제는 **확인 필요**.
- 신원: 채널 단위 사용자 키. 실명·전화번호는 사용자가 말해 줘야 앎.
- 맞는 환경: 이동 중, 한 손, 짧은 질문, 비기술 사용자, 여러 사람이 각자 폰으로.
- 함정: 여러 칸 입력 폼, 표, 관리자 화면, 긴 처리 중 진행 표시(콜백 1회 구조면 불가).

### 모바일 앱 (네이티브·하이브리드)
- 도달 2: 설치·로그인 장벽. 스토어 심사 기간 **확인 필요**(당일 대회에는 비현실적).
- 입력·출력 5: 카메라·위치·오프라인·풍부한 화면.
- 먼저 말 걸기 5: 푸시 알림(권한 동의 필요).
- 맞는 환경: 매일 반복 사용, 오프라인 사용, 기기 기능(카메라, GPS) 필수.
- 함정: 구현·배포 시간이 가장 김, 업데이트마다 심사.

### 웹앱 / PWA
- 도달 3~4: 주소 하나(바로가기 추가 가능). 설치 없음.
- 입력·출력 4~5: 폼·표·차트·지도, 파일 업로드. 카메라·위치는 브라우저 권한.
- 먼저 말 걸기 2~3: 웹 푸시는 기기·브라우저마다 제약 **확인 필요**.
- 신원: 로그인 또는 링크 토큰 필요 → 비기술 사용자에게 장벽.
- 맞는 환경: 책상 앞 정리·관리자 화면·긴 표·종이 출력.
- 함정: 로그인 설계, 모바일 화면 대응, 호스팅·도메인·HTTPS.

### 웹사이트 (정보 제공 위주)
- 도달 4, 출력 4, 입력 2. 상호작용 적음. 공지·안내·FAQ에 적합.

### 데스크톱 앱
- 도달 2, 출력 5, 오프라인 5. 사무실 단일 PC 업무, 파일 다루기. 배포·업데이트 부담.

### 브라우저 확장 / 호스트 앱 플러그인 (예: 브라우저, 디자인 도구, 협업 도구, 오피스 추가 기능)
- 도달 3: 이미 그 도구에서 일하는 사람에게만. 스토어·관리자 승인 **확인 필요**.
- 강점: 사용자가 이미 보는 화면 위에서 바로 동작(맥락 자동 획득).
- 함정: 호스트 API 제약, 호스트 업데이트에 깨짐, 권한 범위 심사.

### 음성 (스마트 스피커, 전화 ARS, 음성 입력)
- 손이 묶인 환경에 강함. 출력은 짧아야 함, 숫자·목록 전달이 약함. 소음 환경에 약함.

### 알림 채널 (문자, 알림톡, 이메일)
- 먼저 말 걸기 전용. 대화형이 아님. 알림톡은 사업자·템플릿 승인 필요(**확인 필요**).
- 챗봇의 보조 표면으로 자주 쓰인다(〈업무 이름〉 처리 결과 알림).

### 스프레드시트 연동 (구글 시트·엑셀 추가 기능)
- 이미 엑셀로 일하는 사람에게 도달 4. 데이터 입력·정리에 강함, 대화형 약함.

## 결합 패턴 (주 표면 + 보조 표면)

| 패턴 | 언제 | 비용·주의 |
|---|---|---|
| 챗봇 + 읽기 전용 웹 페이지 링크 | 긴 표·종이 출력·관리 화면이 꼭 필요할 때 | 공개 경로·호스팅·인증 필요. 이 대회 프로젝트에서는 프록시 설정 변경 = 인프라 변경 → D1 |
| 챗봇 + 알림 채널 | 처리 결과·리마인더를 놓치면 안 될 때 | 승인·한도. 챗봇 자체의 선제 발송으로 충분한지 먼저 확인 |
| 웹앱 + 메신저 공유 | 관리하는 사람은 책상, 함께 일하는 사람들은 이동 중 | 두 표면의 신원 연결 |
| 앱 + 오프라인 동기화 | 신호가 없는 곳 | 충돌 해결 설계 |

## 형태가 고정됐을 때 (대회처럼)

- 형태를 다시 논의하지 않는다. **요구 → 지원/우회/불가 → 패턴·비용·잃는 것** 표를 만든다.
- 핵심(에이전트 그래프·도구·데이터·기억)은 표면과 분리한다. 응답 빌더(말풍선·버튼 변환)만 플랫폼에 의존하게 둔다 → 대회 뒤 웹·앱으로 다시 포장할 수 있다.
- 고정 형태로 must 요구를 못 채우면 "플랫폼을 바꾸자"가 아니라 **범위 결정(D1)** 또는 **보상 패턴**으로 올린다.
