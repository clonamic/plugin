# 실행 종류와 단계 (pipelines)

`src/fde_mode/planner.py`의 `PIPELINES`를 사람이 읽게 옮긴 것이다. 각 단계는 먼저 **스크립트**(코드, 밀리초)를 실행하고 그다음 **에이전트**를 띄운다. 한 단계의 에이전트가 모두 끝나야(유효한 출력, 또는 2번 실패) 다음 단계로 간다. 여러 실행이 동시에 돌 수 있다.

## 언제 저절로 생기나 (triggers, `fde next`가 매번 확인)

| 실행 | 생기는 조건 |
|---|---|
| `R07-quick` 빠른 라운드 | 대화 붙여넣기가 저장될 때마다 |
| `R01-brief` 문제 설명 분석 | `>>brief` 붙여넣기 |
| `R09-debate` 토론 라운드 | 대화 라운드가 `debate_every`(기본 3)의 배수 번째로 빠른 분석을 마쳤을 때(스위치 `debate`) |
| `TG1` 기술 게이트 | must 요구사항이 2라운드 연속 안 바뀌고 라운드 ≥3, 또는 핵심 동결 30분 전(스위치 `tech_gate`) |
| `FZ-core-N` 핵심 동결 | 동결 검사 통과 + 대화 라운드 ≥ `min_rounds_before_freeze`(기본 3) + 분석 중인 라운드 없음(라운드 보고 직후, 시각과 별개), 또는 핵심 동결 시각이 지남, 또는 좌석이 `kind: build_start`로 일찍 시작을 요청함(알림 한 줄, 그 라운드 뒤 바로). "인터뷰 계속"이면 그때까지 끝난 대화 라운드 수를 기준으로, 다음 라운드(이미 붙여넣은 라운드 포함)의 분석이 끝난 뒤 다시. 그래도 핵심 동결이 없으면 전체 동결 계획 시각에 한 번 더 묻는다(강제 동결 없음). "이것만 더 확인하고 시작"이면 그 카드가 다 닫힌 뒤(또는 핵심 동결 시각이 지나면) 다시 |
| `BUILDPLAN` → `S01`… | 핵심 동결 승인 직후 |
| `DATA-NN` | 바인딩의 `data_raw` 폴더에 새 파일이 생겼을 때(스위치 `division_data`) |
| `CLOSING` | 기능 동결 시각이 지났을 때(P1~P5 — 핵심 동결을 안 했어도 시작, 그때는 지금 배포된 것이 제출본이고 spec.md를 오늘 요구사항으로 쓴다) |
| `RB-…` 되돌리기 | 배포 실패 |
| 수동 | `fde run debate|techgate|freeze|change|retro|closing|rehearsal|rehearsal-grade ...` |

## debate — 토론 라운드 (백그라운드, 인터뷰는 계속)

| # | 이름 | 에이전트 |
|---|---|---|
| 0 | 준비 | — |
| 1 | 개별 분석 | 켜진 본부의 분석가 전원(같은 라운드 빠른 분석 결과는 재사용) |
| 2 | 팀 내 보완 | 같은 팀 동료 결과를 읽고 한 번 이어받기(스위치 `team_complement`) |

| 9 | 질문 카드·결론 | 질문 작성가, (3라운드마다) 확인 요약 작성가, 서기장(회의록), 엔게이지먼트 리드(관점 충돌 분석 포함) |

## brief — 문제 설명 분석

심사 관점 분석가, 도메인 전문가, 범위 매니저, 플랫폼 제약 검사관, 데이터 수집 계획가, 환경 분석가, 패키징 전략가(brief 모드) → 후보 통합관 → 독립 검증 → 질문 작성가 + 엔게이지먼트 리드(opening: 인터뷰 첫 계획) → 보고

## techgate — 기술 결정 게이트

런타임·데이터 아키텍트, 통합 담당, 플랫폼 제약, 비용 추정, 패키징 전략가(tech 모드) → 반대 위원 → 테크 리드(ADR + D1/D2 결정) → 완료 알림

## freeze — 동결

동결 검사(스크립트) + spec 초안 → 동결 판단관 + 문서 일관성 감사관 → 사용자 D1 "제작 시작해도 될까요? (핵심 동결)"(전체는 "확장 기능까지 닫아도 될까요? (전체 동결)")(대기). 맥락: 내부 확신 · must 근거 n/m · 영향 높음 열린 질문 · 지금 시작하면 가정으로 넘어갈 질문 · 막는 항목 / 판단 / 막는 항목 / 부족한 정보(받으면 바뀌는 것).

| 선택지(핵심 · 전체) | 판단관 `recommend` | 결과 |
|---|---|---|
| 제작 시작 · 전체 동결 | `freeze` | 요구사항 잠금, spec.md 확정, P4, 구현 계획 시작 |
| 이것만 더 확인하고 시작 · …동결 | `confirm_first` | 판단관 `missing_info` 상위 3개가 바로 질문 카드(영향 높음, "제작 전 확인"). 다 닫히면(또는 핵심 동결 시각이 지나면) 같은 D1을 다시 올린다(전체 동결은 `fde run freeze --level full`로 다시) |
| 인터뷰 계속 | `wait` | 다음 라운드의 분석이 끝난 뒤 다시, 전체 동결 계획 시각에 한 번 더 |
| 막는 항목만 가정으로 처리하고 시작 · …동결 | `freeze_with_assumptions` | 열린 질문을 가정으로 바꾸고 동결 |

선택지 라벨(+"(추천)")과 짧은 말("제작 시작", "시작", "동결", "지금 동결" 등), 예전 라벨("지금 동결", "아직 (인터뷰 계속)")만 받는다. 그 밖의 자유 글은 동결하지 않고 다시 묻는다.

## buildplan → slice (조각마다)

테크 리드(plan) → 조각 실행 생성. 조각은 15단계다. ★는 협업 모드(기본, 스위치 `autonomy` 꺼짐)에서 사용자에게 묻는 곳이고, 자율 모드면 추천을 적용하거나 건너뛴다.

| # | 이름 | 하는 일 |
|---|---|---|
| 0 | 이전 조각 대기 | 앞 조각 실행이 끝날 때까지(협업이면 앞 조각의 진행 확인 답까지) |
| 1 | 설계 | 설계 본부장 + 필요한 설계자 + 디테일 설계자(항상) |
| 2 | 설계 확인 ★ | 설계 출력의 `decision_points`를 D2 "[설계·조각 N] <제목>"(등급 D1이면 D1)으로 묻고 답이 다 올 때까지 대기 → `runs/<조각>/design-choices.json`. 자율이면 추천을 적용해 같은 파일(`mode: autonomy`) |
| 3 | 명세 추적 | 명세 추적관(입력에 `design_choices`) |
| 4 | 구현 | 파일이 겹치지 않는 작업끼리 묶어서. 입력 `design_choices`. 협업이면 메모에 "진짜 갈림길은 혼자 정하지 말고 `tasks_blocked`에 `design_question`으로" |
| 5 | 구현 중 설계 질문 ★ | 막힌 작업의 `design_question`을 D2 "[구현 중 설계·B-xxx] <제목>"으로 → 답이 오면 그 작업을 재작업으로 되돌리고 리뷰 메모 "사용자 설계 답(D-…): … → …"를 붙여 4로 |
| 6 | 독립 리뷰 | 코드 리뷰어, 명세 대조관 |
| 7 | 리뷰 판정 | 반려면 4로(최대 2번) |
| 8 | 에스컬레이션 결정 | 2번 반려: 개발 본부장 + D1 |
| 9 | 배포 ★ | 한 번에 하나. 협업이면 첫 배포와 되돌린 뒤 첫 배포만 D2 "조각 N을 배포할까요? (첫 배포/되돌린 뒤 첫 배포)" [배포, 보류(이유를 적어 주세요)] — 보류면 조각 중단(failed), 지금 배포된 버전 유지 |
| 10 | QA | QA 7석(시나리오·가상 사용자·응답 시간·표시 형식·적합성·UX·AI티) |
| 11 | QA 판정 | QA 본부장 |
| 12 | 릴리스 | 릴리스 관리자(정상 태그) + 관측 |
| 13 | 마무리 | 통과면 사람에게 카톡 실기 요청, 실패면 수정 조각 생성 |
| 14 | 진행 확인 ★ | QA 통과 뒤 D2 "조각 N 배포·QA 통과. 다음은 어떻게 할까요?" [다음 조각 진행(남은 조각이 없으면 이대로 유지), 수정 요청(무엇을 고칠지 적어 주세요), 설계 재검토]. 자유 글 = 수정 요청 → 변경 통제 `CH-NN`, 설계 재검토 → 재계획 `RP-<조각>-review`, 라벨만 오면 고칠 내용을 다시 묻는다. 다음 조각은 이 답을 기다린다 |

- 협업 D2는 조각마다 `[collab] max_questions`(기본 4)개까지다(설계 확인·구현 중 설계 질문에만 — 첫 배포 확인·진행 확인은 늘 묻는다). 넘으면 추천으로 D3 자동 + 알림 "질문 상한(4개)을 넘어 추천으로 진행합니다…". D1은 상한이 없다.
- 답 "추천대로"·"추천"·"추천안"은 그 결정의 추천 라벨로 기록된다.

## data — 데이터 (파일이 들어올 때마다)

데이터 리드(dataplan) → 검증관 + 인터뷰 대조 검사관 → 정제 담당 → 적재 담당 → 출처 감사관(독립) → 데이터 리드(datareport)

## change, closing, retro, rehearsal

- change: 변경 영향 분석관 → 사용자 결정 대기 → 테크 리드 재계획(`RP-CHANGE-NN`: 반영이면 새 조각, 미룸·거절이면 작업 없음). 분석관이 결정을 안 냈으면(명확화) 거기서 끝
- closing: 최종 QA 7석 → QA 본부장 + 데모 시나리오 작가 → 릴리스 관리자(최종 태그) + 서기장(최종 보고서) → 제출 체크리스트(사람)
- retro: 회고 분석가 → 교훈을 `~/.clonamic/fde-mode/lessons.md`에 누적
- rehearsal: 가짜 인물(봉인 파일 생성) / rehearsal-grade: 리허설 채점관(봉인 해제 후)
