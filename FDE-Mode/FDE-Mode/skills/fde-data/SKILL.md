# 데이터 트랙 (수집 · 검증 · 정제 · 적재)

대회 미션에 "데이터 수집·검증·정제"가 들어 있다. 데이터 본부는 인터뷰와 구현 양쪽에 걸쳐 움직인다.

## 1. 데이터가 들어오는 길

- 인물이 파일·표를 주면 사용자가 바인딩의 `data_raw` 폴더(예: `data/raw/`)에 넣는다. `fde next`가 새 파일을 발견하면 `DATA-NN` 실행이 저절로 생긴다.
- 인물에게 데이터를 받아야 하면(예: "예시 하나만 보여주세요") 데이터 수집 계획가가 질문 후보로 낸다. 일반 질문 카드와 같은 검증을 거친다.
- 공개 데이터가 필요하면 데이터 수집 계획가가 출처를 찾아 제안하고, 받을지 여부는 사용자 결정(D2)이다.
- 합성 데이터는 반드시 "합성"으로 표시한다. 진짜 데이터인 것처럼 봇이 말하게 만들지 않는다.

## 2. 흐름 (`DATA-NN`)

데이터 리드(계획: 파일마다 쓰임새와 요구사항 연결) → 데이터 검증관(형식, 결측, 중복, 이상값, 날짜·인코딩) + 인터뷰 대조 검사관(인물의 말과 데이터가 맞는지: 수량, 이름, 가격, 일정) → 정제 담당(정제 규칙을 프로젝트의 적재 코드에 넣고 다시 실행, 행을 조용히 버리지 않음) → 적재 담당(바인딩 명령으로 로컬·서버 표 적재, 문서는 벡터 저장소로, 적재 뒤 질의로 확인) → 출처 감사관(독립: 출처, 라이선스, 합성 표시, 봇이 주장할 내용의 정직성) → 데이터 리드(보고와 결정).

## 3. 디렉터가 사용자에게 가져오는 것

- 인물 말과 데이터가 어긋난 곳 → 질문 카드로(인물에게 확인).
- 결측치 처리, 이상값 제외, 컬렉션 재생성처럼 되돌리기 어렵거나 의미가 바뀌는 것 → D1/D2 결정.
- 벡터 컬렉션 재생성(`RECREATE=1` 같은 것)은 사람별 기억 벡터도 지울 수 있어 가드가 사용자 확인을 요구한다.
- 적재 결과(행 수, 거른 행, 남은 문제)를 3줄로.

## 4. 주의

- 표 데이터가 서버에 반영되는 경로를 바인딩에서 확인한다. 로컬 SQLite가 배포 때 업로드에서 빠지는 프로젝트라면, 서버 쪽 적재 명령(`ingest_table_remote`)을 써야 한다.
- 데이터 파일 자체는 사용자 저장소의 무시 목록에 있을 수 있다(예: `data/raw/`). 원본은 지우지 않는다.
