# 동결과 변경 통제 (P3)

인터뷰를 계속하면 질문은 끝없이 나온다. 질문하는 시간은 곧 구현 시간에서 빠진다. 그래서 "이제 그만 묻고 만들어도 된다"를 판단하는 장치가 따로 있다. 동결은 단계적이다: **핵심 동결**로 구현을 먼저 출발시키고, 인터뷰는 확장 기능 위주로 계속한 뒤 **전체 동결**한다.

## 1. 핵심 동결 기준 (코드 검사 `fde freeze-check core`)

- must 요구사항이 있고, 모두 근거 없는 가정 상태가 아니다(명시 또는 확인된 추론).
- 영향 높음 + 확신 [확실]/[가능성 높음]인 열린 질문이 0개.
- must 요구사항마다 수용 테스트가 1개 이상.
- 플랫폼상 "불가"인 must가 없다(대안 합의 완료).
- 핵심 동결을 막는 D1 결정이 없다.

검사가 통과하고(막는 항목 0) 대화 라운드가 3번 이상이면 라운드 보고 직후 동결 판단 실행이 저절로 생긴다 — 시각과 별개다. 핵심 동결 시각(바인딩 `[schedule] core_freeze`)이 지나면 통과 여부와 상관없이 판단을 묻는다.

## 2. 흐름

1. 동결 검사(코드) + spec.md 초안 생성.
2. **동결 판단관**이 권고한다: 제작 시작(`freeze`) / 이것만 더 확인하고 시작(`confirm_first`) / 인터뷰 계속(`wait`) / 막는 항목만 가정으로 처리하고 시작(`freeze_with_assumptions`). 함께 내는 것: 내부 확신(확실·가능성 높음·추측)과 그 근거 수치, 부족한 정보(받으면 무엇이 바뀌는지, 인물에게 물을 질문), 지금 시작하면 가정으로 넘어가는 항목. **문서 일관성 감사관**이 인물 모델·요구사항·spec 사이의 불일치를 찾는다.
3. 디렉터가 D1로 묻는다: **"제작 시작해도 될까요? (핵심 동결)"**. 맥락 한 줄은 엔진이 만든 그대로 붙인다(숫자는 코드가 셌다):
   `내부 확신 [가능성 높음] · must 근거 3/4 · 영향 높음 열린 질문 1 · 지금 시작하면 가정으로 넘어갈 질문 2 · 막는 항목 1 / 판단: … / 막는 항목: … / 부족한 정보: 〈업무 이름〉을 누가 최종 승인하는지(받으면: 승인 요청 흐름)`
   선택지 네 개, 판단관 추천을 맨 위에 "(추천)":
   - **제작 시작**: must 요구사항 잠금, spec.md 확정, 단계 P4, 구현 계획(테크 리드) 시작. 인터뷰는 계속(P5).
   - **이것만 더 확인하고 시작**: 부족한 정보 상위 3개가 바로 질문 카드로 나온다(영향 높음, "제작 전 확인" 표시). 사용자가 인물에게 묻고 답을 붙여넣어 카드가 다 닫히면(또는 핵심 동결 시각이 지나면) 엔진이 같은 D1을 다시 올린다. 판단관이 부족한 정보를 적지 않았으면 카드 없이 인터뷰를 계속한다(알림).
   - **인터뷰 계속**: 다음 대화 라운드 뒤에 다시 판단한다.
   - **막는 항목만 가정으로 처리하고 시작**: 열린 질문을 모두 가정으로 기록하고 동결. 가정 목록은 spec.md "묻지 않고 가정한 것"에 남는다(발표에서 설명 가능).
4. 답 해석(`planner._freeze_choice`): 선택지 라벨 그대로("(추천)" 꼬리는 괜찮다), 짧은 말("제작 시작", "시작", "동결", "지금 동결" 등), 예전 라벨("지금 동결", "아직 (인터뷰 계속)")만 받는다. 사용자가 직접 쓴 다른 답(예: "조금 더 물어보고요", "제작 시작하지 마세요")은 동결로 치지 않고 엔진이 같은 결정을 다시 올린다 — 그때 선택지로 다시 묻는다.

## 3. 전체 동결

확장 기능(should)까지 정리되면 `fde run freeze --level full`. 기준은 핵심 동결 + should의 근거 없는 가정 없음 + 영향 높음 열린 질문 0개. D1은 "확장 기능까지 닫아도 될까요? (전체 동결)"이고 선택지는 전체 동결 · 이것만 더 확인하고 동결 · 인터뷰 계속 · 막는 항목만 가정으로 처리하고 동결이다. 전체 동결에서 "이것만 더 확인"은 카드만 만들고 저절로 다시 묻지 않는다 — 카드가 닫히면 `fde run freeze --level full`로 다시 연다. 전체 동결 뒤 새 요구는 변경 통제로만 들어간다.

## 4. 변경 통제 (동결 뒤의 새 요구)

- 요구사항 관리관이 동결된 요구사항과 충돌하는 새 발화를 표시하거나, 인물이 새 기능을 원하면 `fde run change --text "<요약>"`.
- **변경 영향 분석관**이 바뀌는 요구사항·파일·작업과 예상 시간, 권고(수용/미룸/거절)와 등급을 낸다.
- D1/D2로 묻고, 수용하면 구현 작업으로 들어간다. 구현 중인 조각을 중간에 바꾸지 않고 그 조각 배포 뒤에 반영한다.
- 기능 동결 시각 이후의 변경은 원칙적으로 거절을 권고한다(마감 모드).
