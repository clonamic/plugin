# 인터뷰 단계 (P1, P5)

사용자가 인물(페르소나)과 대화하고, 그 대화를 이 세션에 붙여넣는다. 조직은 붙여넣기마다 빠른 라운드를 돌려 **다음에 물어볼 질문**과 **사용자가 정할 결정**을 나눠서 돌려준다. 이 단계의 목표는 질문을 많이 만드는 것이 아니라, **핵심 동결까지 필요한 것만 정확히 묻는 것**이다.

## 1. 붙여넣기

- 훅(UserPromptSubmit)이 붙여넣은 원문을 **고치지 않고** `inbox/R07.transcript.raw.md`로 저장하고, 발화 단위(U001…)로 나눠 DB에 넣는다. 디렉터는 저장된 원문을 다시 읽지 않는다.
- 판별 규칙: 첫 줄이 `>>`(대화), `>>brief`(문제 설명), `>>메모`(사용자 메모)면 확실하다. 터미널 붙여넣기의 감싸기 꼬리표(`pasted_content`)는 벗기고 보며, 표지는 직접 친 첫 줄이든 붙여넣은 글의 첫 줄이든 된다. 저장하지 못한 붙여넣기는 훅이 "저장하지 않았다"로 알린다 — 사용자에게 "표지를 직접 치고 다시 붙여 넣어 주세요"를 한 줄로 전한다. 표지(`>>`·`>>brief`·`>>메모`)를 치고 Shift+Enter로 줄을 바꾼 뒤 붙여 넣고 Enter(Enter만 누르면 표지만 전송된다). 또는 클립보드 맨 윗줄에 표지를 넣어 한 번에 붙여 넣는다. 표지만 보냈다면 10분 안에 바로 다음 메시지로 붙여 넣으면 그 종류로 저장된다. 붙여넣기 안에서는 표지와 본문이 같은 줄이면 표지로 보지 않는다. 표지만 온 메시지에는 훅이 "표지만 받았다"를 알리니 사용자에게 "다음 메시지로 붙여 넣으세요"를 전한다. 표시가 없으면 화자 표시(`이름:` 또는 이름만 있는 줄)가 반복되는지로 자동 판별한다(스위치 `auto_detect_paste`). 자동 판별이었는데 대화가 아니었다면 `fde undo-paste R07`.
- 훅이 알려 주는 경고를 사용자에게 한 줄씩 전한다:
  - "이전 붙여넣기와 겹친 발화 N개를 뺐습니다" — 정상(복사할 때 앞부분이 겹치는 경우)
  - "직전 질문에 대한 인물 답이 빠졌을 수 있습니다" — 사용자에게 빠진 부분을 다시 붙여 달라고 한다
  - "화자가 불확실한 발화 N개" — 기록관이 확인한다. 사용자가 화자 이름을 알려 주면 `fde speakers <이름> I|P --round R07`
- 그다음 `fde next` → 빠른 라운드(포그라운드)를 같은 턴에 끝까지 돌린다.

## 2. 보고서 전하기

빠른 라운드가 끝나면 `reports`의 텍스트에서 다음을 그대로 보여 준다.

1. **지금 물어볼 질문** 최대 5개 — 각 카드의 배지([확신 | 영향 | 표시]), 붙여넣을 질문(인용 블록), 근거 발화, 답에 따라 바뀌는 것.
2. ⚠ 불일치 카드는 렌즈와 검증관 판단을 나란히 두고 "직접 판단이 필요합니다".
3. **다음 10분 인터뷰 전략**(엔게이지먼트 리드).
4. **인터뷰어 코치** 2~3줄(내가 빠뜨린 영역, 모호한 답 뒤에 파고들지 않은 횟수 등).
5. 결정이 필요한 것 → 바로 AskUserQuestion(fde-director 4절).

보류·가정 제안·탈락 목록은 "대시보드에 있습니다"로 줄인다. 사용자가 가정 제안에 반대하면 해당 항목을 질문으로 되돌린다(`fde question <Q-id> open`).

## 3. 질문이 물어졌는지 추적

- 사용자가 카드를 복사해 인물에게 보내면, 다음 붙여넣기에서 그 문장이 인터뷰어 발화로 나타난다. 코드가 카드와 대조해 **물어봄**으로 바꾸고 이어진 인물 답을 연결한다(따로 표시할 필요 없음).
- 카드를 고쳐서 물었다면 연결이 안 될 수 있다. 그때는 `fde question Q-012 asked`.
- 물을 필요가 없어졌으면 `fde question Q-012 dropped`, 가정으로 갈 거면 `assumed`.

## 4. 토론 라운드

- 대화 라운드가 3번 쌓일 때마다(바인딩 `debate_every`) 토론 라운드가 백그라운드로 시작된다. 인터뷰는 계속한다.
- 사용자가 "지금 토론 돌려"라고 하거나, 엔게이지먼트 리드가 큰 모순을 경고하면 `fde run debate`.
- 토론 라운드 보고서는 빠른 라운드보다 늦게 도착한다. 그 사이에 들어온 발화와 대조한 "낡은 항목" 표시를 함께 전한다.

## 5. 확인 요약 (readback)

3라운드마다 확인 요약 작성가가 "제가 이해한 내용을 정리해 볼게요" 문단을 만든다. 일부러 확신이 낮은 부분을 넣어 인물이 고칠 기회를 준다. 사용자에게 "이 요약을 인물에게 보여 주고 고쳐 달라고 해 보세요"라고 권한다. 인물이 고친 부분은 다음 붙여넣기에서 일관성 추적가가 잡는다.

## 6. 문제 설명과 데이터

- `>>brief`로 문제 설명을 붙이면 브리프 분석(심사 관점, 도메인, 범위, 플랫폼, 데이터, 환경, 패키징)이 돌아 **인터뷰 첫 계획과 첫 질문**이 나온다. 대회 시작 직후(문제 정독 시간)에 하면 좋다.
- 인물이 파일이나 표를 줬다면 바인딩의 `data_raw` 폴더에 넣으라고 안내한다. 데이터 본부가 자동으로 시작한다(fde-data 스킬).

## 7. 멈추는 기준

- 동결 검사가 통과하고 대화 라운드가 3번 이상이면 동결 판단 실행이 저절로 생긴다(fde-freeze). 핵심 동결 시각이 지나면 통과 여부와 상관없이 묻는다.
- 남은 시간은 훅이 매 턴 보여 준다. 시간 예산 관리자의 경고가 나오면 그대로 전한다.

## 8. P5 — 구현과 병행하는 인터뷰

핵심 동결 뒤에도 인터뷰는 확장 기능 위주로 계속된다. 요구사항 관리관이 동결된 요구사항과 충돌하는 새 발화를 표시하면 `fde run change --text "<요약>"` → 변경 영향 분석관 → 결정(D1/D2). 구현 중인 조각을 중간에 바꾸지 않고, 그 조각이 배포된 뒤에 반영한다.
