# 고쳐 쓰기 처방

[ai-tells](ai-tells.md)에서 걸린 신호를 실제 문장으로 고칠 때 쓴다. 예문은 한다체로 적었지만 결과의 문체 높낮이는 언제나 원문을 따른다. 예문의 격식을 베끼지 않는다.

## 원칙

1. **의미 불변.** 사실, 주장, 수치, 고유명사, 인용, 인과 관계는 글자 그대로 둔다. 모호해도 임의로 보강하지 않는다.
2. **어조 유지.** 격식체는 격식체로, 에세이는 에세이로. 다른 장르로 옮기지 않는다.
3. **국소성.** 걸린 구간만 고친다. 문단 전체를 새로 쓰지 않는다.
4. **빼기 전용.** 처방 예시의 어휘를 원문에 없던 자리에 새로 심지 않는다. 원문보다 격식을 올리지 않는다. “~인데요”, “~거든요”, “~한 겁니다” 같은 구어 종결은 사람 글의 증거다.
5. **자연스러움이 완벽함보다 앞선다.** 지나치게 문학적으로 고치지 않는다. 평범한 한국어 필자의 중간 리듬을 목표로 한다.
6. **입말은 결함이 아니다.** 쉽고 생생한 입말 문장을 한자어 명사 사슬로 바꾸면 더 나쁜 티가 된다.

## 고치는 순서

상투구 → 번역 뼈대 → 형식 명사 → 유보 → 접속 → 수식 → 영어 끼워 넣기 → 형식과 장식 → 리듬.

앞쪽은 지우는 일이 많고, 뒤쪽은 지운 결과를 다듬는 일이다. 리듬을 먼저 손보면 앞의 수정이 리듬을 다시 흐트러뜨린다.

## 번역 뼈대

| 원문 | 고친 예 |
|---|---|
| X에 대해 논의한다 | X를 논의한다 |
| X에 있어서 | X에서 / X를 볼 때 |
| X라는 점에서 | X해서 / X이기 때문에 |
| X와 관련하여 | X에서 / X를 두고 |
| X에 기반하여 | X로 / X를 근거로 |
| 경쟁력을 가지고 있다 | 경쟁력이 있다 / 경쟁력이 강하다 |
| 판단되어진다 | 판단된다 |
| AI에 의해 생성된 | AI가 만든 |
| X을 위해 Y한다 | X하려고 Y한다 / X하도록 Y한다 |
| 합의가 이루어졌다 | 합의했다 |
| 기술 발전 속도 가속화 | 기술이 빨리 발전한다 |
| 높일 수 있다 | 높인다(원문이 사실로 말할 때만) / 높일 여지가 있다(가능성일 때) |

관형구가 길면 나눈다.

- “그는 사고를 일으킨 화학물질을 생산한 회사에서 한때 일했던 한 남자를 만났다.” → “그는 한 남자를 만났다. 사고를 일으킨 화학물질을 만든 회사에서 한때 일했던 사람이다.”

## 대칭 대구

지시만 주면 쉼표만 지우고 끝나기 쉽다. 한쪽을 길게 풀고 다른 쪽은 짧게 끊거나, 한 문장을 둘로 나누거나, 대구의 한 축을 다른 화제로 잇는다.

- “기술은 도구이고, 사람은 주체다. 데이터는 연료이며, 알고리즘은 엔진이다.” → “기술은 도구다. 사람이 그 도구를 쥔다. 데이터가 있어야 알고리즘이 돌아간다.”
- “중요한 것은 속도가 아니라 방향이며, 양이 아니라 질이다.” → “속도보다 방향이 중요하다. 양은 그다음 문제다.”
- “기계는 답을 주지만, 질문은 주지 않는다.” → “기계는 답을 준다. 질문은 여전히 사람 몫이다.”

잘 쓴 대구 하나는 남긴다. 막연한 의미 부여로 끝나는 대구는 앞쪽을 지우고 뒤쪽을 구체적으로 말한다. 구체적인 내용이 원문에 없으면 대구를 평서문으로 풀기만 한다.

## 분열문과 결산 공식

- “주 4일제 논쟁의 핵심은 생산성 전환이다.” → “주 4일제 논쟁은 생산성을 어떻게 바꾸느냐로 모인다.”
- “문제는 양측이 합의에 이르는 경우가 거의 없다는 점이다.” → “양측은 합의에 이르는 일이 거의 없다.”
- “그 부담은 결국 소비자 가격으로 전가된다. … 결국 세금으로 돌아온다.” → 뒤의 “결국”만 남기거나 둘 다 뺀다.
- “일률적인 도입이 현실적이지 않은 이유다.” → “그래서 일률적인 도입은 현실적이지 않다.”

결말을 다듬으면서 “~하는 이유다”, “~해야 한다”를 새로 만들지 않는다.

## 상투구

| 대상 | 처리 |
|---|---|
| 결론적으로, 요약하면, 정리하자면 | 뺀다. 마지막 문단이 이미 결론이다 |
| ~라고 할 수 있다 | 원문이 이미 사실로 말했을 때만 “~이다”. 관측이면 “~로 보인다”. 유보를 단정으로 올리지 않는다 |
| 매우 중요하다 | 근거로 바꾼다. “X 없이는 Y가 안 된다” |
| 시사하는 바가 크다, 주목할 만하다 | 뺀다 |
| 혁신적인, 획기적인 | 대부분 뺀다. 필요하면 “처음 시도한”, “이전과 다른”처럼 구체화한다 |
| ~의 지평을 열다, ~시대가 도래했다 | 빼고 실제 변화를 쓴다 |

## 비유

기본은 직설이다. 비유는 다섯 조건을 모두 채울 때만 쓴다. (1) 대상이 낯설거나 추상적이다. (2) 이해를 돕는다. 꾸미기만 하지 않는다. (3) 직설보다 짧다. (4) 오해를 부르지 않을 만큼 정확하다. (5) 소리 내어 읽어도 어색하지 않다. 하나라도 어긋나면 직설로 쓴다.

여정, 전쟁터, 생태계, 엔진과 연료, 북극성, 플라이휠, DNA, 빙산, 다리 같은 은유는 업무 글에서 생각이 약한 것을 가린다. “녹여 냈다”, “담아냈다”, “엮어 냈다” 같은 은유 동사는 “넣었다”, “뺐다”, “바꿨다”, “보였다”, “줄였다”처럼 구체 동사로 바꾼다.

## 유보

서법 보존이 먼저다. 완곡을 걷는 일과 유보를 단정으로 바꾸는 일은 다르다.

- 겹친 완곡만 줄인다. 완곡 한 단계는 반드시 남긴다. “~할 수 있을 것으로 보인다” → “~로 보인다”는 된다. “~로 보인다” → “~이다”는 안 된다.
- 같은 추측 종결이 반복되면 강도는 그대로 두고 형태만 바꾼다. “~로 보인다 / ~인 듯하다 / ~로 읽힌다 / 아직 단정하기는 이르다”.
- 단정으로 내려도 되는 경우는 하나뿐이다. 원문의 다른 문장이 같은 사실을 이미 확정적으로 말했을 때.

## 접속

- 문두 접속사가 3개 이상 연속이면 논리적 일을 하지 않는 것을 뺀다.
- “따라서”, “그러므로”는 인과가 뻔하면 빼고, 필요하면 “그래서”로 바꾼다.
- “하지만”과 “그러나”가 번갈아 반복되면 한쪽을 “그런데”로 바꾸거나 뺀다.

## 형식 명사

- “변화가 크다는 것이다” → “변화가 크다”
- “~할 필요가 있다”는 문맥에 따라 “~하자”, “~하는 게 맞다”, 주체를 밝힌 동사로 바꾼다. “~해야 한다”로 일괄 바꾸지 않는다.
- “혁신이 필요하다” → 맥락이 허락하면 누가 무엇을 해야 하는지로 구체화한다. 맥락이 없으면 둔다.

## 수식

- “근본적 변화” → “뿌리부터 바뀐다”
- “구조적 문제” → “구조가 문제다”
- 동의어를 겹친 수식은 하나만 남긴다.

## 영어 단어

광고성 외래어만 한국어로 풀고, 업계 표준 기술 용어는 원어로 둔다. 기계적으로 직역하지 않는다(prompt → “지시문”으로 바꾸지 않는다).

| 영어·외래어 | 한국어 |
|---|---|
| leverage, 레버리지 | 활용하다, 기대다 |
| seamless | 매끄러운, 끊김 없는 |
| robust | 튼튼한, 견고한 |
| insight, 인사이트 | 통찰, 알게 된 점 |
| impact, 임팩트 | 영향, 효과, 바꾼 것 |
| 어필하다 | 보여 주다, 내세우다 |
| deep dive, 딥다이브 | 깊이 살펴보기, 자세히 |
| holistic | 전체적인 |
| As-Is / To-Be | 현재 / 바꾼 뒤 |

## 서식

- 불릿 → 산문: “- 속도가 빠르다 / - 비용이 저렴하다 / - 확장성이 높다” → “속도는 빠르고 비용도 낮다. 무엇보다 확장 여지가 크다.” 실제 항목 목록(기술 스택, 일정, 절차)은 목록으로 둔다.
- 칼럼과 에세이의 H2 이상 제목은 흐름으로 대신할 수 있다. 보고서, 기술 문서, 포트폴리오의 제목 구조는 둔다.
- 굵은 글씨는 제목과 꼭 훑어야 할 한두 곳만. 줄표는 문서당 1~2회.

## 리듬

- 균일하면 문단마다 짧은 문장 하나와 인접 문장을 이은 긴 문장 하나를 섞는다. 내용은 보태지 않는다.
- 같은 종결이 4~5문장 이어지면 “~었다 / ~ㄴ다 / ~기 마련이다 / ~ㄹ 것이다”처럼 섞는다. 시제와 서법은 유지한다.
- 소리 내어 읽어 숨이 막히는 문장은 나누고, 툭툭 끊기는 곳은 잇는다.
