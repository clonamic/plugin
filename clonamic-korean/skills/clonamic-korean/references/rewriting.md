# 고쳐 쓰기 처방

[ai-tells](ai-tells.md)에서 걸린 문장을 실제로 고칠 때 쓴다. 예문은 한다체와 합쇼체를 섞어 적었다. 결과의 문체 높낮이는 언제나 원문을 따른다.

## 지킬 것

1. **뜻은 그대로.** 사실, 주장, 수치, 이름, 인용, 원인과 결과는 바꾸지 않는다. 문장이 모호해도 내 짐작으로 채우지 않는다.
2. **말투는 그대로.** 보고서는 보고서로, 블로그는 블로그로 둔다. 격식도 한 단계라도 높이지 않는다(`-했-`을 `-하였-`으로 바꾸지 않는다).
3. **걸린 곳만.** 문단을 통째로 새로 쓰지 않는다. 한 문장에서도 걸린 구절만 손댄다.
4. **덜어 내는 쪽으로.** 아래 고친 예의 낱말을 원문에 없던 자리에 심지 않는다. 처방표는 치환표가 아니다.
5. **보통 사람의 문장.** 문학적으로 꾸미지 않는다. 일 잘하는 동료가 쓴 메일 정도의 리듬이 목표다.
6. **입말은 살린다.** `~거든요`, `~인데요`, `~한 겁니다` 같은 구어 종결과 쉬운 입말은 사람이 쓴 흔적이다. 한자어 명사 덩어리로 바꾸면 더 나빠진다.

## 고치는 순서

상투구 → 근거 없는 틀 → 번역 뼈대 → 형식 명사 → 유보 → 접속 → 수식 → 영어 끼워 넣기 → 형식과 장식 → 규범([norms](norms.md)) → 리듬.

앞쪽은 지우는 일이고 뒤쪽은 남은 문장을 고르는 일이다. 리듬을 먼저 만지면 앞의 수정이 리듬을 다시 흐트러뜨린다.

## 번역 뼈대

| 걸린 꼴 | 고친 예 |
|---|---|
| 장애 원인에 대해 분석했다 | 장애 원인을 분석했다 |
| 성능 개선에 있어서 가장 큰 걸림돌은 | 성능을 개선할 때 가장 큰 걸림돌은 |
| 보안과 관련하여 점검했다 | 보안을 점검했다 |
| 로그 데이터에 기반하여 판단했다 | 로그를 보고 판단했다 |
| 높은 확장성을 가지고 있다 | 확장하기 쉽다 |
| 검토되어진 안 | 검토한 안 / 검토된 안 |
| 문서에 쓰여진 절차 | 문서에 쓰인 절차 |
| 운영팀에 의해 배포되었다 | 운영팀이 배포했다 |
| 테스트를 자동화시켰다 | 테스트를 자동화했다 |
| 배포를 더 안전하게 만들었다 | 배포가 더 안전해졌다 |
| 고객사로부터 요청을 받았다 | 고객사에게서 요청을 받았다 / 고객사가 요청했다 |
| 신규 가입자의 경우 | 신규 가입자는 |
| 서울에 위치한 사무실 | 서울에 있는 사무실 |
| 왜 실패했는가를 정리했다 | 왜 실패했는지 정리했다 |
| 여러 문제들이 겹쳤다 | 여러 문제가 겹쳤다 |
| 비용 절감을 위해 캐시를 붙였다 | 비용을 줄이려고 캐시를 붙였다 |
| 점검이 이루어졌다 | 점검했다 |
| 처리 속도 향상 | 처리 속도가 빨라졌다 (원문이 사실로 말할 때) |

`에 의해`를 고칠 때 행위자가 원문에 없으면 만들지 않는다. `가지고 있다`가 실제 소유면 둔다. `할 수 있다`를 `한다`로 바꾸는 것은 원문이 사실로 말할 때만이다. 가능성이면 `할 여지가 있다`처럼 유보를 남긴다.

관형절이 길게 겹치면 문장을 나눈다.

- “지난달 결제 오류를 일으킨 외부 모듈을 공급한 업체와 계약했던 담당자를 만났다.” → “담당자를 만났다. 지난달 결제 오류를 일으킨 외부 모듈의 공급 업체와 계약했던 사람이다.”

## 대칭 대구

지시만 받으면 쉼표 하나 지우고 끝내기 쉽다. 구조를 실제로 바꾼다. 한쪽은 풀어 쓰고 한쪽은 짧게 끊거나, 두 문장으로 나누거나, 한 축을 다음 화제로 넘긴다.

- “속도는 무기이고, 품질은 방패다.” → “빨리 내놓는 게 무기였다. 품질은 그 뒤를 받쳤다.”
- “문제는 도구가 아니라 습관이며, 해법은 규칙이 아니라 문화다.” → “도구보다 습관이 문제였다. 규칙만 늘려서는 바뀌지 않았다.”
- “자동화는 시간을 아껴 주지만, 판단은 대신해 주지 않는다.” → “자동화로 시간은 아꼈다. 무엇을 배포할지는 여전히 사람이 정한다.”

잘 쓴 대구 하나는 남긴다. 뒤쪽이 막연한 의미 부여면(“결국 태도의 문제다”) 앞쪽을 지우고 원문에 있는 구체적인 내용을 직접 말한다. 그런 내용이 원문에 없으면 대구를 평서문으로 풀기만 한다.

## 분열문과 결산 공식

- “이번 개편의 핵심은 검색 속도다.” → “이번 개편은 검색 속도에 집중했다.”
- “문제는 로그가 너무 늦게 쌓인다는 점이다.” → “로그가 너무 늦게 쌓였다.”
- “비용은 결국 사용자에게 넘어간다. … 결국 신뢰를 잃는다.” → 둘 중 하나의 `결국`만 남기거나 둘 다 뺀다.
- “수동 배포를 없애야 하는 이유다.” → “그래서 수동 배포를 없애야 한다.”

결말을 다듬으면서 `~하는 이유다`, `~해야 한다`를 새로 만들지 않는다.

## 상투구

| 걸린 말 | 처리 |
|---|---|
| 결론적으로, 요약하면, 정리하자면 | 뺀다. 마지막 문단이 이미 결론이다 |
| ~라고 할 수 있다 | 원문이 단정했으면 `~이다`, 관찰이면 `~로 보인다`. 유보를 단정으로 올리지 않는다 |
| 매우 중요하다 | 왜 중요한지로 바꾼다. “이 값이 틀리면 정산이 멈춘다” |
| 시사하는 바가 크다, 주목할 만하다 | 뺀다 |
| 혁신적인, 획기적인 | 대부분 뺀다. 필요하면 “처음 시도한”, “전과 다른”처럼 사실로 |
| 새 지평을 열다, 시대가 열렸다 | 빼고 실제로 바뀐 것을 쓴다 |
| 앞서 말씀드린 것처럼, 이 글에서는 ~을 살펴보겠습니다 | 뺀다 |

## 근거 없는 틀

- 원문에 없는 “흔히”, “일반적으로”, “업계에서는”, “전문가들은”을 문장 연결용으로 넣지 않는다. 원문에 있으면 두고, 출처가 필요해 보이면 결과 끝에 묻는다.
- 처음 보는 개념어가 정식 용어처럼 나오면(“이른바 배포 피로 편향”) 실제 용어인지 확인한다. 확인할 수 없으면 하려던 말로 푼다(“배포가 잦아지자 사람들이 검토를 건너뛰었다”). 원문의 다른 곳에 그 내용이 없으면 표시만 한다.
- “사용 경험이 매끄러웠다”가 원문의 실제 기능을 가리고 있으면 그 기능을 앞으로 꺼낸다(“검색어를 지우지 않고 필터만 바꿀 수 있었다”). 원문에 그런 기능이 없으면 만들지 않는다.

## 비유

업무 글의 기본은 직설이다. 원문의 비유를 남길지 정할 때는 그 비유를 지우고 직설로 한 번 써 본다. 직설 문장이 더 길고 흐릿해질 때만 비유를 남긴다. 독자가 처음 보는 추상적인 대상을 설명하는 비유는 남을 때가 많고, 이미 아는 것을 꾸미는 비유는 대개 빠진다. 잘못 읽힐 여지가 있는 비유는 짧아도 뺀다.

자주 걸리는 것은 거창한 은유와 은유 동사다.

- 여정, 전쟁터, 생태계, 엔진, 나침반, 퍼즐 조각, 씨앗, 날개 같은 은유가 업무 문장에 나오면 실제로 일어난 일로 바꾼다. “검색 기능은 서비스의 엔진이다” → “사용자 요청의 절반이 검색이다”(원문에 그 사실이 있을 때).
- “녹여 냈다”, “담아냈다”, “엮어 냈다”, “불어넣었다”, “꽃피웠다”는 “넣었다”, “바꿨다”, “줄였다”, “보여 줬다”처럼 한 일을 그대로 쓴다.
- 고치면서 원문에 없던 비유를 새로 만들지 않는다.

## 유보

서법을 지키는 것이 먼저다. 겹겹이 쌓인 완곡을 한 겹으로 줄이는 일과, 추측을 사실처럼 말하게 바꾸는 일은 전혀 다르다.

- 겹친 완곡만 줄이고 한 단계는 남긴다. “늘어날 수 있을 것으로 예상된다” → “늘어날 것으로 보인다”는 된다. “늘어날 것으로 보인다” → “늘어난다”는 안 된다.
- 같은 추측 종결이 이어지면 강도는 두고 꼴만 바꾼다. “~로 보인다 / ~일 가능성이 있다 / ~인 듯하다 / 아직 단정하기는 어렵다”.
- 단정으로 바꿔도 되는 때는 하나다. 같은 사실을 원문이 다른 곳에서 이미 단정해 말했을 때.

## 접속

- 문두 접속사가 셋 이상 이어지면 논리를 실제로 잇지 않는 것부터 뺀다.
- 뻔한 인과의 “따라서”, “그러므로”는 빼고, 필요하면 “그래서”로 쓴다.
- “하지만”과 “그러나”가 번갈아 나오면 하나를 “그런데”로 바꾸거나 뺀다.

## 형식 명사

- “배포 주기가 짧아졌다는 것이다” → “배포 주기가 짧아졌다”
- “~할 필요가 있다”는 문맥에 따라 “~해야 한다”, “~하자”, 주체를 밝힌 동사로. 한 가지로 일괄 바꾸지 않는다. 의무의 강도는 그대로 둔다.
- “개선이 필요하다”는 맥락이 허락하면 누가 무엇을 고칠지로 구체화한다. 맥락이 없으면 둔다.

## 수식

- “전략적 판단” → “전략 판단”, “근본적인 원인” → “뿌리 원인” 또는 “원인”
- “구조적 한계” → “구조가 한계다”
- 같은 뜻을 겹친 수식(“핵심적이고 중요한”)은 하나만 남긴다. 겹친 낱말은 [norms](norms.md)의 표를 본다.

## 영어 단어

광고성 외래어만 한국어로 풀고 업계에서 그대로 쓰는 기술 용어는 둔다. 기계적으로 직역하지 않는다(`prompt`를 `지시문`으로, `token`을 `토막`으로 바꾸지 않는다).

| 외래어 | 한국어 |
|---|---|
| 레버리지하다 | 활용하다, 기대다 |
| 심리스한 | 매끄러운, 끊김 없는 |
| 로버스트한 | 튼튼한, 잘 버티는 |
| 인사이트 | 알게 된 점, 통찰 |
| 임팩트 | 영향, 효과, 바꾼 것 |
| 어필하다 | 보여 주다, 내세우다 |
| 딥다이브 | 깊이 살펴보기, 자세히 |
| 얼라인하다 | 맞추다 |
| As-Is / To-Be | 지금 / 바꾼 뒤 |

## 서식

- 불릿을 산문으로: “- 설치가 쉽다 / - 문서가 많다 / - 커뮤니티가 크다” → “설치가 쉽고 문서도 많다. 막히면 물어볼 사람도 많다.” 실제 목록(기술 스택, 일정, 절차)은 목록으로 둔다.
- 칼럼과 에세이는 큰 제목 대신 문단 흐름으로 이을 수 있다. 보고서, 기술 문서, 포트폴리오의 제목 구조는 둔다.
- 굵은 글씨는 제목과 꼭 훑어야 할 한두 곳에만. 줄표는 문서에 한두 번.

## 리듬

- 길이가 고르면 문단마다 짧은 문장 하나와 이웃 문장을 이은 긴 문장 하나를 섞는다. 내용은 보태지 않는다.
- 같은 종결이 네댓 번 이어지면 “~했다 / ~였다 / ~한 셈이다”처럼 어미만 섞는다. 시제와 서법은 바꾸지 않는다.
- 소리 내어 읽어 숨이 차는 문장은 나누고, 툭툭 끊기는 곳은 잇는다.
