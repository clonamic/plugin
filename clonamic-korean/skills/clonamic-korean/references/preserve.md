# 보존과 대조

사실을 바꾸면 다른 글이 된다. 고치기 전에 보존 목록을 만들고, 고친 뒤 원문과 대조한다.

## 그대로 둔다

- 사실, 주장, 수치, 날짜, 단위, 비율, 금액
- 고유명사, 제품명, 기관명, 모델명, 기술 용어(vLLM, RAG, CER, API, prompt, token)
- 말했다, 밝혔다, 따르면처럼 발화 표지가 붙은 직접 인용. 필자가 자문하거나 강조하려고 따옴표로 감싼 자기 문장은 고칠 수 있다.
- 법률 조문, 수식, 통계 표기, 각주 번호와 각주 내용
- 코드 블록, 인라인 코드, 명령어, 경로, 링크
- 제목 구조와 절 순서. 깊게 고치기에서도 사용자가 구조 변경을 요청하지 않았으면 둔다.
- 당위와 추측의 강도(서법)
- 원문의 문체 높낮이. 격식은 격식으로, 구어는 구어로
- 필자가 정한 범위. 요청받은 부분만 고친다.

## 내용 앵커

고치기 전에 문장마다 주장을 이루는 핵심 명사와 개념어를 적는다. 조사와 어미는 바꿀 수 있다. 그 원형 어휘는 결과에 최소 한 번 그대로 남긴다. 상투구나 추상어를 덜어 낼 때는 수식어와 형식 명사만 걷는다. 앵커까지 사라질 것 같으면 그 문장을 되돌린다.

## 서법

- 당위(“~해야 한다”, “~할 필요가 있다”, “시급하다”)를 사실 단정(“~한다”)으로 바꾸지 않는다.
- 추측(“~일 수 있다”, “~로 보인다”, “~로 판단된다”)을 단정으로 바꾸지 않는다. “낮은 것으로 판단된다”를 “낮은 수치다”로 바꾸면 의미가 바뀐다.
- 서법의 보존과 표지의 반복은 다른 문제다. 같은 표지가 반복돼 리듬을 지배하면 서법은 그대로 두고 배치만 바꾼다. 당위로 끝나는 문단이 여럿이면 그 문장을 문단 앞이나 중간으로 옮긴다. 지우거나 다른 서법으로 바꾸지 않는다.
- 법률, 의료, 금융, 계약 문장의 의무와 주장 강도는 손대지 않는다.

## 넣지 않는다

- 원문에 없는 사실, 수치, 백분율, 배수, 출처, 인물, 일화. 원문 숫자로 계산한 값도 사용자가 요청할 때만 넣고 근거를 함께 적는다.
- 원문에 없는 이유나 평가. 이유가 빠져 아쉬우면 필자에게 묻는 항목으로 적는다.
- 원문에 없던 상투구(“기록적인 성과”, “로 평가된다”, “중요한 역할을 한다”)와 과장(“100%”, “원천 차단”, “완벽히”).
- 원문에 없던 비유와 수사.

## 과다 수정 한도

다듬기와 가볍게에서 글자 변경률 30%는 경고, 50% 이상은 그 결과를 완료로 내지 않는다. 깊게 고치기는 사용자가 큰 변경을 요청한 것이므로 50%를 넘어도 경고로만 보지만, 사실·인용·숫자 규칙은 똑같이 적용한다. 변경률이 5% 미만이면 이미 좋은 글일 가능성이 크다. 억지로 더 고치지 않는다.

## 검사기

```bash
python3 scripts/check_revision.py --before 원문.txt --after 결과.txt [--deep] [--json]
```

경로는 이 스킬 폴더 기준이다. 원문과 결과는 임시 폴더에 둔다. 사용자 프로젝트에 남기지 않는다.

| 종료 코드 | 뜻 | 할 일 |
|---|---|---|
| 0 | 통과 | 결과를 낸다 |
| 1 | 확인 필요 | `[확인]` 항목을 하나씩 본다. 정당한 변경이면 결과 요약에 이유를 적고, 아니면 그 문장을 되돌린다 |
| 2 | 채택 금지 | `[위반]` 문장을 원문으로 되돌리고 다시 검사한다 |
| 3 | 입력 오류 | 파일 경로와 인코딩(UTF-8)을 확인한다. 판정을 건너뛰지 않는다 |

위반은 결과가 비어 있음, 원문에 없던 수치, 바뀐 직접 인용, 바뀐 코드 블록, 다듬기에서 변경률 50% 이상이다. 확인 항목은 사라진 수치와 영문 용어, 새 영문 표현, 서법 표현 감소, 문체 높낮이 변화, 과장·외래어·상투구·명사화·관찰자 말투 증가, 굵은 글씨·이모지·번호 항목 증가, 제목 변화, 대구 전멸이다.

검사기는 문체를 평가하지 않는다. 통과가 곧 좋은 글이라는 뜻은 아니다. 한글 고유명사(사람 이름, 회사 이름)는 기계로 가려낼 수 없으니 직접 대조한다.

## 수동 대조표

검사기를 실행할 수 없는 환경에서는 원문과 결과를 나란히 놓고 이 순서로 확인한다. 결과에는 수동으로 확인했다고 적는다.

1. 원문의 숫자를 모두 찾아 결과에 같은 값이 있는지, 결과에 원문에 없는 숫자가 생기지 않았는지 본다.
2. 고유명사와 기술 용어가 같은 표기로 남았는지 본다.
3. 발화 표지가 붙은 인용, 코드, 링크가 글자 그대로인지 본다.
4. “해야”, “필요”, “수 있다”, “보인다”, “판단된다” 같은 표현이 줄지 않았는지 본다. 줄었다면 그 문장의 서법이 그대로인지 본다.
5. 종결 어미의 높낮이가 같은지, “-하였-”이 늘지 않았는지 본다.
6. 제목, 절 순서, 범위가 같은지 본다.
7. 새로 생긴 과장, 외래어, 굵은 글씨, 이모지, 번호 목록이 없는지 본다.
