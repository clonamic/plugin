# 쉽게 풀어 쓰기

글이 빽빽해서 한 번에 읽히지 않을 때 쓴다. 안내문, 설명 글, 기술·금융·제도처럼 추상적인 주제에서 효과가 크다. 이미 자연스럽게 읽히는 짧은 글에는 쓰지 않는다.

## 무엇을 쉽게 하나

쉽게 쓴다는 것은 내용을 가볍게 줄이거나 모든 한자어를 순우리말로 바꾸는 일이 아니다. 읽는 사람이 문장 구조를 해석하느라 쓰는 불필요한 힘을 줄이는 일이다. 생각은 깊어도 문장 구조가 명확하면 한 번에 읽힌다.

한국어 글을 무겁게 만드는 원인은 대개 네 가지다.

1. **현학적인 한자어 서술어.** `제고하다`, `도모하다`, `상이하다`, `용이하다`처럼 일상 업무에서도 잘 쓰지 않는 굳은 서술어.
2. **명사로 굳힌 동작.** `점검을 실시했다`, `개선을 진행했다`, `검토를 수행했다`.
3. **겹친 관형절.** 명사 하나 앞에 꾸밈 절이 둘 셋 쌓여 주어와 서술어 사이가 멀어진 문장.
4. **설명 없이 나온 낯선 전문어.** 독자가 모르는 용어나 약어가 맥락 없이 등장하는 것.

기준은 분명하다. 그 분야를 모르는 동료가 한 번 읽고도 핵심을 이해할 수 있으면서, 동시에 전문성이나 정확함이 떨어지지 않는 문장이다.

## 고치는 법

- **정착된 개념어(명사)는 유지하고, 서술어(동사·형용사)만 자연스럽게 푼다.**
  쉽게 쓴다고 해서 업계와 일상에서 표준으로 쓰는 한자어 명사까지 억지 순우리말이나 유아어처럼 풀면 오히려 문장이 어색해진다.
  - **바꾸지 않는 개념어 예:** `전달 데이터`, `역할 분담`, `외부 독자`, `예외 처리`, `반복 한도`, `구현`, `배포`, `정산`, `검증`. (이를 `나르는 데이터`, `역할 나누기`, `바깥 사람`, `기능 말`처럼 억지로 풀지 않는다.)
  - **쉽게 푸는 서술어 예:**

  | 무거운 서술어 | 자연스러운 서술어 |
  |---|---|
  | 제고하다 | 높이다 |
  | 도모하다 | 꾀하다, 추진하다(또는 구체적 동사) |
  | 상이하다 | 다르다 |
  | 용이하다 | 쉽다 |
  | 기인하다 | ~ 때문이다, ~에서 비롯되다 |
  | 수반하다 | 따르다, 함께 생기다 |
  | 초래하다, 야기하다 | 일으키다, 낳다 |
  | 규명하다 | 밝히다 |
  | 상존하다 | 늘 있다, 남아 있다 |
  | 요구되다 | 필요하다 |

- **동작은 동사로 쓴다.** `점검을 실시했다` → `점검했다`, `개선을 진행했다` → `개선했다` 또는 `고쳤다`. 동작 명사 뒤에 `실시`, `진행`, `수행`, `시행`이 붙어 있으면 본동사로 바로 쓸 수 있는지 본다.
- **한 절에 한 생각을 담고 자연스럽게 잇는다.** 관형절이 여러 겹으로 겹치면 수식받는 명사를 먼저 말하고 설명을 뒤 절이나 다음 문장으로 보낸다. 이때 무조건 짧은 단문으로만 끊지 말고, 원인과 결과는 `~해`, `~하므로`, `~기 때문에`로 자연스럽게 연결한다.
- **낯선 전문어는 처음 나올 때 한 번 풀어 준다.** 독자가 이미 공유하는 기술 용어는 그대로 둔다. 개발자 문서에서 API를 풀어 쓸 필요는 없지만, 일반 사용자 안내문에서는 처음 한 번 쉽게 덧붙인다.
- **주어를 분명히 세운다.** `요청이 접수되면 처리가 진행됩니다` → `요청을 받으면 담당자가 처리합니다`. 다만 원문에 행위자가 없을 때는 억지로 주어를 지어내지 않는다.
- **추상어보다 구체적인 대상을 쓴다.** `관련 기능`보다 `내보내기 버튼`, `효율 향상`보다 원문에 있는 실제 변화나 수치를 쓴다.
- **이중 부정은 긍정으로 푼다.** `해당하지 않는 경우를 제외하고는` → `해당하면`. 다만 부정이나 예외 조건 자체가 법적·기술적 요건이면 원문 그대로 둔다.
- **실제 예시를 든다.** 추상적인 정의를 길게 늘이는 것보다 구체적인 예시 하나가 이해를 돕는다. 예시는 원문이나 사용자 자료에서 가져오고, 새로 든 예시는 예시라고 밝힌다.
- 공지와 안내문의 굳은 행정 투(`상기`, `익일`, `의거하여`)는 [norms](norms.md)의 표를 따른다.

## 다른 기준과 부딪치지 않게

- **리듬.** 말을 쉽게 푼다고 모든 문장을 짧게 토막 내지 않는다. 구조가 자연스러운 문장은 조금 길어도 한숨에 읽히며, 짧은 단문만 나열하면 오히려 기계가 쓴 글처럼 어색해진다.
- **구체성.** 숫자, 고유명사, 실제 사례는 글을 명확하게 만든다. 쉽게 쓴다는 이유로 구체적인 정보를 지우지 않는다.
- **목소리.** 필자의 고유한 어조와 자연스러운 구어는 살리고, 불필요하게 얽힌 수식 구조만 정돈한다.
- **사실.** 풀어 쓰는 과정에서 의미의 범위가 넓어지거나 좁아지지 않게 한다. 조건과 유보는 그대로 유지한다.

## 무게 가늠

- 소리 내어 읽었을 때 숨이 차거나 앞부분을 다시 읽게 되는 문장이 손볼 대상이다.
- 한 문장이 60자를 훌쩍 넘으면서 관형절이 두세 겹 쌓여 있으면 절을 나누거나 어순을 정돈한다.
- 한 문단에 `-적`, `-성`, `-화`와 굳은 한자어 서술어가 과도하게 몰려 있으면 동사 중심으로 푼다.
- 설명 없이 등장한 낯선 약어와 용어를 확인한다.

## 진단 형식

진단만 요청받았으면 어색한 문장을 그대로 인용하고 자연스럽게 고친 안을 함께 제시한다.

```text
쉽게 풀기 진단
- 굳은 한자어 서술어: "서비스 접근성 제고를 도모하고자 합니다" → "서비스를 더 쉽게 이용할 수 있게 개선하려고 합니다"
- 명사로 굳힌 동작: "전수 점검을 실시하였습니다" → "전부 점검했습니다"
- 겹친 관형절: "지난주 배포된 결제 모듈에서 발생한 오류로 인해 지연된 정산"
  → "지난주 배포한 결제 모듈에서 오류가 나 정산이 늦어졌다."
- 설명 없는 약어: "SLA 기준" → 처음 한 번 "서비스 수준 협약(SLA) 기준"
```
