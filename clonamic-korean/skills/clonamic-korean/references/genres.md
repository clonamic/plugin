# 문서 종류별 기준

장르를 정하면 화자, 문체 높낮이, 허용되는 서식이 정해진다. 다듬기에서는 원문의 선택을 따르고, 새로 쓰기에서는 아래를 기본값으로 쓴다. 사용자가 준 지침이 있으면 그쪽이 먼저다.

| 장르 | 화자와 높낮이 | 허용 | 피할 것 |
|---|---|---|---|
| 이력서·경력기술서 | 1인칭, 주어 생략. 합쇼체 또는 명사형 종결(“~함”, “~구축”)을 문서 안에서 하나로 | 한 줄 성과, 기술 스택 목록, 기간 | 광고 문구, 근거 없는 수치와 기여율, “본 지원자는” |
| 포트폴리오·프로젝트 소개 | 1인칭 합쇼체 | 문제 → 선택 → 결과 흐름, 실제 숫자, 짧은 제목 | 제3자 보고서 말투(“~로 적혀 있습니다”), 과장, 외래어 제목 |
| 자기소개서 | 1인칭 합쇼체 | 구체적인 장면과 계기, 문항 글자 수 한도 | 상투적 시작(“어릴 때부터”), 모든 문단을 교훈으로 맺기, 문장마다 “저는” |
| 보고서·기획서 | 한다체 또는 합쇼체, 문서 관례를 따른다 | 결론 먼저, 제목 1~2단계, 표와 통계, 출처 | 과장, 이모지, 결산 상투구, 출처 없는 “~라는 분석이다” |
| 기술 문서·README | 해라체 명령형 또는 합쇼체, 저장소 관례를 따른다 | 절차 목록, 코드 블록, 표 | 코드·명령어·경로를 고치는 일, 마케팅 어휘 |
| 블로그·게시글 | 필자 목소리, 해요체나 한다체 | 질문, 짧은 문장, 개인 경험 | “오늘은 ~에 대해 알아보겠습니다”, 기계적 “첫째, 둘째” |
| 칼럼·에세이 | 한다체 | 단문, 개인 어조, 필요한 비유 하나 | 이모지, 과한 제목, 불릿 나열, 경구형 결말 반복 |
| 공적 글·축사·공지 | 합쇼체 격식 | 정중한 관용 표현 | 구어, 이모지, 불릿, 사물 높임(“준비되셨습니다”), 굳은 행정 말투(“상기”, “익일”) |
| 화면 문구·알림·웹 페이지 | 제품이 정한 높낮이(대개 해요체나 합쇼체). 라벨은 짧은 명사형 | 짧은 문장, 동작을 알려 주는 버튼 | 자리표시자·태그 바꾸기, 화면마다 다른 말투, 감상형 제목 |

## 이력서와 포트폴리오

- 문장의 주인은 필자다. 필자가 한 일을 동사로 쓴다. “~를 담당함”보다 “~를 만들었습니다”가 뚜렷하다.
- 숫자는 원문에 있는 것만 쓴다. 숫자가 없으면 무엇을 바꿨는지 구체적으로 쓴다. 숫자를 만들지 않는다.
- 기여도는 비율보다 맡은 일을 적는다. 사용자가 비율을 피하라고 했으면 어떤 비율도 쓰지 않는다.
- 선택에는 이유가 있어야 읽힌다. 이유가 원문에 없으면 필자에게 묻는다.
- 한계와 남은 일은 범위로 담담하게 적는다. 변명처럼 문서를 끝내지 않는다.
- 기술 용어는 개발자가 실제로 말하는 표기를 쓴다(vLLM, RAG, CER).

## 자기소개서

- 문항이 묻는 것에 첫 문장에서 답한다. 배경 설명으로 시작하지 않는다.
- 글자 수 한도는 공백 포함인지 제외인지 확인하고 검사기로 센다([norms](norms.md)). 한도를 채우려고 군말을 보태지 않는다.
- 경험은 장면과 행동으로 쓴다. “소통 능력을 길렀다”보다 그때 실제로 한 일을 쓴다. 원문에 없는 일화는 만들지 않는다.
- 문장마다 “저는”으로 시작하지 않는다. 주어가 바뀔 때만 쓴다.

## 화면 문구와 웹 페이지

- 같은 화면, 같은 흐름 안의 문구는 높낮이와 용어를 맞춘다. 한 문구만 다른 말투면 주변 문구 쪽으로 맞춘다.
- `{name}`, `%s`, HTML 태그 같은 자리표시자와 마크업은 글자 그대로 둔다([preserve](preserve.md)).
- 버튼과 메뉴는 짧게, 무엇이 일어나는지 알 수 있게 쓴다. 오류 문구는 무엇이 잘못됐고 무엇을 하면 되는지 쓴다.

## 보고서

- 첫 문단에 결론과 요청을 둔다. 배경은 그 뒤에 둔다.
- 판단에는 근거를, 근거에는 출처를 붙인다. 출처가 없으면 만들지 않고 표시한다.
- 유보와 당위의 강도를 바꾸지 않는다. “검토가 필요하다”를 “도입한다”로 바꾸면 결정이 바뀐다.

## 기술 문서

- 독자가 따라 할 순서대로 쓴다. 한 단계에 한 동작.
- 코드, 명령어, 경로, 설정 키는 글자 그대로 둔다.
- 영어 기술 용어는 번역하지 않는다. 처음 나오는 낯선 용어만 한 번 풀어 준다.

## 게시글

- 첫 문장에서 무엇에 관한 글인지 알 수 있어야 한다. 도입은 [openings](openings.md).
- 경험담이면 실제 장면과 실제 숫자를 쓴다. 흐름은 [story](story.md).
- 해시태그와 이모지는 플랫폼 관례만큼만 쓴다.
