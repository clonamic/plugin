# 섹션 작성 규칙

문서의 구조(섹션 이름, 순서, 표의 칸, 번호와 링크)는 스크립트가 고정해서 만든다. 여기서는 각 칸에 **무엇을 담고 무엇을 담지 않는지**만 정한다. 글자 수나 문장 수 제한은 없다. 결정에 필요한 내용만, 같은 사실은 한 곳에만 쓴다. 꾸밈말, 일반론, 당연한 말은 쓰지 않는다. 변수 이름, 함수 이름, 코드 용어, 파일 경로, 프롬프트 원문은 어디에도 쓰지 않는다.

## 프로젝트

| 칸 | 담을 것 | 담지 않을 것 |
|---|---|---|
| 목적 한 줄 | 무엇을 받아 무엇을 내놓는지 | 기술 이름 |
| 원하는 것 | 사용자 말에 가까운 결과 모습 | 하는 일 나열 |
| 배경 | 왜 필요한가(있을 때만) | 일반론 |
| 성공 기준 | 완성 여부를 판단할 수 있는 기준 | "잘", "적절히" 같은 판별할 수 없는 말 |
| 받는 것 / 내놓는 것 | 파이프라인 전체의 입력과 출력. 항목 이름은 용어 사전과 같게 | 중간 데이터 |
| 하지 않는 것, 제약 | 범위 밖의 일, 반드시 지킬 조건(응답 시간, 개인정보, 비용 한도, 언어) | 구현 세부 |
| 도구 | 필요한 능력을 먼저, 추천 도구와 대안은 옆에 | 능력 없이 제품 이름만 |
| 사람 개입 지점 | 사람이 판단하는 지점과 그동안 흐름 | — |
| 검증 시나리오 | 정상 하나와 예외 몇 개. 입력, 거치는 경로(번호), 기대 결과. 성공 기준을 모두 확인할 수 있게 | 코드 단위 테스트 |
| 설계 결정 | 결정, 이유, 버린 대안 | 거절된 제안, 사소한 문구 변경 |
| 미결 사항 | 아직 정하지 못한 것 | 이미 정한 것 |

## 에이전트

| 칸 | 담을 것 | 담지 않을 것 |
|---|---|---|
| 이름 | 짧은 기능명(예: 여행 계획) | 문장 |
| 역할 한 줄 | 이 에이전트가 맡는 역할 하나 | 내부 단계 나열 |
| 의도 | 왜 독립된 에이전트로 나눴나. 다른 에이전트에 합치지 않은 이유 | 하는 일 다시 쓰기 |
| 맡지 않는 것 | 다른 에이전트와 헷갈릴 수 있는 일 중 하지 않는 것 | — |
| 출구 | 흐름이 끝나는 경우마다 하나. 이름과 언제 | 이어질 에이전트 설명 |
| 고정과 재량 | 고정: 구현 방식이 달라도 지킬 것. 재량: 구현하는 사람이나 AI가 정해도 되는 것 | 언어·프레임워크 선택(원래 재량) |
| 주요 경로 | 정상과 예외 경로를 문장으로(있을 때만) | — |
| 공통 주의점 | 모든 단계에 반복되는 제약을 한 번만 | 단계 하나에만 해당하는 것 |

## 단계

| 칸 | 담을 것 | 담지 않을 것 |
|---|---|---|
| 이름 | 짧은 기능명(예: 설계 검토, 질문 생성, 여행 정보 분석) | 문장, 번호 |
| 유형 | 판단(AI가 판단), 처리(정해진 규칙), 외부 연동(도구·서비스), 사람 확인 | — |
| 한 줄 요약 | 이 단계가 하는 일 한 줄 | 이유 |
| 의도 | 이 단계가 왜 있나. 없으면 무엇이 깨지나 | 하는 일 다시 쓰기, 일반론 |
| 하는 일 | 처리 순서. 고르는 기준이 있으면 여기에. 너무 많아지면 단계를 쪼갤지 검토 | 이유, 도구 이름, 다음 단계가 할 일 |
| 받는 것 / 내놓는 것 | 용어 사전 이름 | 새 이름, 담기는 내용 설명 |
| 도구 | 필요한 능력, 용도, 추천 도구 | — |
| 완료 기준 | 다음으로 넘어가도 되는 조건 | 판별할 수 없는 말 |
| 고정과 재량 | 판단 단계라면 특히 채운다 | 구현 기술 선택 |
| 예시 | `받음: … → 내놓음: …` 한 건 | 실제 개인정보, 꾸민 수치를 사실처럼 |
| 주의점 | 구현할 때 놓치기 쉬운 점 | 모든 단계에 해당하는 일반론 |
| 실패 시 | 실패가 분기를 만들 때만 | "실패 없음" |

## 연결

| 칸 | 담을 것 | 담지 않을 것 |
|---|---|---|
| 종류 | 항상 / 조건 | — |
| 이름 | 조건 연결이면 조건 요약(예: 후보 부족). 항상 연결은 비워 두면 도착 이름이 쓰인다 | 문장 |
| 조건 | 실제로 판별할 수 있는 규칙 | "필요할 때", "적절하면", 같은 출발의 다른 연결과 겹치는 조건 |
| 판단 주체 | 정해진 규칙 / AI 판단 / 사람. 규칙으로 될 일은 규칙으로 | — |
| 반복 탈출 | 되돌아가는 연결이면 탈출 연결과 횟수 | — |
| 의도 | 왜 이 분기가 필요한가 | 단계가 하는 일 다시 쓰기 |
| 넘기는 것 | 용어 사전 이름 | 새 이름 |

## 용어 사전

- 문서 두 개 이상에서 쓰이는 데이터만 올린다. 처음 생기는 곳과 쓰이는 곳은 스크립트가 채운다.
- 담기는 내용: 구현하는 사람이 같은 모양으로 만들 수 있게 무엇이 들어 있는지 쉬운 말로 쓴다(예: 날짜, 장소, 이동 순서, 예상 비용). 변수 이름은 쓰지 않는다.
- 같은 것을 다른 이름으로 부르지 않는다(예: 여행 조건 / 여행 요구사항).
