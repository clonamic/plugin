# clonamic-create-agent

## 핵심 요약

- 사용자와 AI가 대화하며 에이전트 파이프라인을 노드와 간선의 그래프로 설계하고, 그 설계를 구현 방식에 묶이지 않는 문서로 끝까지 정리하는 플러그인이다.
- 명령은 `/clonamic-create-agent [프로젝트명 또는 만들고 싶은 것]` 하나이고, 사용자가 직접 입력했을 때만 실행된다.
- 실행하면 로컬 웹 편집기가 열린다. 가운데 캔버스에서 그래프를 보고 고치고, 오른쪽 사이드바에서 각 노드와 연결의 내용을 채우며, 검토 챗봇이 설계를 객관적으로 평가해 제안한다.
- 결과물은 사용자가 지정한 폴더에 내보내는 설계 문서 묶음이다. 전체 흐름(Mermaid), 에이전트 문서, 단계 문서, 연결 문서, 데이터 사전, 변경 이력으로 이루어진다. 구현하는 사람이나 AI가 이 문서만 보고 바로 만들 수 있을 만큼 구체적으로 쓰는 것이 목표다.
- 코드는 만들지 않는다. 문서를 스킬(.md), 플러그인, 웹, 앱, Hermes, LangGraph 등 어디로든 옮겨 구현할 수 있게 하는 것이 목적이다.

## 1. 문제 정의

- AX 자동화의 기본은 여러 기능이 모여 하나의 파이프라인을 이루는 것이다. 그래서 설계 단계가 결과를 좌우한다.
- 파이프라인은 기능과 분기로 이루어진다. 노드와 간선으로 생각하는 LangGraph의 방식이 이 구조를 가장 잘 담는다.
- 설계에는 세 가지가 필요하다.
  - 한눈에 보기: 전체 흐름이 시각적으로 바로 보여야 한다.
  - 재현성: 정확한 문서만으로 누구나 같은 파이프라인을 다시 만들 수 있어야 한다.
  - 쉬운 수정: 파이프라인마다 나중에 고치기 쉬워야 한다.
- 이 플러그인은 파이프라인을 한눈에 보여 주고, 쉽게 고칠 수 있게 하며, 설계와 그 과정을 여기서 완전히 문서화한다.

## 2. 목표와 범위

| 구분 | 내용 |
|---|---|
| 하는 것 | 사용자의 요구사항을 확인하고, 에이전트와 단계의 그래프를 설계하고, 객관적으로 검토하고, 설계와 결정 과정을 문서로 완성한다 |
| 하지 않는 것 | 코드 생성, 실행, 테스트. 특정 구현 방식(프레임워크, 언어)에 맞춘 문서 |
| 문서의 쓰임 | 사람이 직접 코드로 구현, 스킬이나 플러그인으로 구성, 웹·앱·Hermes·LangGraph 등으로 구현, AI에게 맡겨 구현 |

- LangGraph는 설계 사고의 틀(노드, 연결, 조건 분기, 시작과 끝, 하위 그래프)로만 쓴다. 문서에는 LangGraph 용어나 코드 용어가 드러나지 않는다.
- 문서는 기능과 분기 자체에만 집중하고 깔끔하고 읽기 쉽게 쓴다. 필요한 이유, 조건, 완료 기준 같은 칸은 변수 이름이나 함수 이름 같은 어려운 말 없이 쓴다. 구현 흐름이 필요한 **과정의 이름**과 **도구의 위치·접속**에만 파일·모듈·클래스·함수 이름과 주소를 쓴다.

## 3. 용어

| 용어 | 뜻 |
|---|---|
| AI | 모델이 아니라 Claude Code, Codex, Grok Build, Cursor 같은 에이전트 도구 |
| 에이전트 폴더 | 호스트마다 다른 설정 폴더. `.claude`, `.codex`, `.grok`, `.cursor` 등. 이 문서의 `.claude`는 예시다 |
| 프로젝트 | 설계 하나. 하나의 파이프라인이다 |
| 에이전트 | 역할 하나를 맡는 큰 노드. 1에이전트 = 1기능 |
| 단계 | 에이전트 안에서 그 역할을 이루는 노드. 하나의 기능을 한다 |
| 연결 | 노드와 노드를 잇는 간선. 항상 이어지는 연결과 조건에 따라 갈리는 연결이 있다 |
| input / output | 에이전트나 단계가 받는 데이터와 내놓는 데이터. 에이전트의 input/output은 연결이 나르는 데이터로 자동 계산된다 |
| 다음 | 카드에서 나가는 연결. 조건 연결이면 `조건 → 도착`으로 보인다 |
| 끝 | 흐름이 끝나는 곳. 에이전트 안의 끝은 그 에이전트가 일을 마친 것이고, 다음 에이전트는 에이전트 사이 연결의 조건이 정한다(LangGraph의 END와 조건부 연결) |
| 데이터 사전 | 설계에 나오는 데이터마다 필드(이름, 형식, 필수, 설명, 예)를 적는 곳. 구현할 때 그대로 데이터 구조가 된다 |
| 과정 | 단계 안의 처리 흐름. 파일·모듈·클래스·함수·외부 호출·사람 작업 단위로 순서대로 적고 화살표로 잇는다 |
| 도구 목록 | 프로젝트가 쓰는 도구(MCP 서버, 이 프로젝트의 다른 에이전트, 파일·스크립트, 외부 API, 웹 검색, 데이터베이스, 모델, 기타). 단계와 과정은 번호(T1)로 가리킨다 |
| 제안 카드 | 검토 챗봇이 낸 개선안. 사용자가 "적용"을 눌러야 반영된다 |

## 4. 사용 흐름

1. 사용자가 `/clonamic-create-agent`를 입력한다. 뒤에 만들고 싶은 것을 적으면(예: `여행 일정 짜주는 에이전트`) 첫 요청으로 쓴다.
2. 준비를 확인한다. Python 3.12 이상, clonamic-korean 설치 여부(없으면 설치), 편집기 서버를 확인한다.
3. 브라우저에 편집기가 열린다.
4. **요구사항 인터뷰**: 웹 채팅에서 빈 곳만 한 번에 하나씩, 추천 답과 함께 묻는다. 요구사항, input과 output, 성공 기준, 제약(숫자로), 사람 확인 지점, 쓸 수 있는 도구와 외부 시스템, 범위 밖을 묻는다. 답은 바로 그 칸에 저장된다.
5. **에이전트 구성**: AI가 에이전트와 그 사이 연결(조건, 전달 데이터)을 그린다. 사용자가 역할 나누기와 갈래를 확인한다.
6. **상세 설계**: 에이전트마다 하나씩 단계와 연결, 단계의 모든 칸(과정 행의 input → output, 판단 기준과 AI 지시, 실패 처리, 예시), 데이터 사전의 필드, 도구의 위치·접속을 채운다. 스스로 정할 수 없는 값은 추천 값으로 채우고 설계 결정에 남긴 뒤 에이전트마다 한 번에 확인을 받는다. 구현 준비 점검표(`references/templates.md`)로 빠진 곳을 채운다.
7. **검토**: 검토 챗봇이 구현 가능성을 포함한 기준으로 평가하고 제안 카드를 낸다. 사용자는 직접 고치거나 카드를 적용한다.
8. **내보내기**: 검사 → 한국어 다듬기 제안과 적용 → 문서 생성 순서로 진행한다.
9. 브라우저 탭을 모두 닫으면 끝난다.

- 이미 있는 프로젝트를 열면 인터뷰를 건너뛰고 저장된 상태에서 이어간다.

## 5. 편집기 화면

| 위치 | 내용 |
|---|---|
| 왼쪽 사이드바 | 프로젝트 목록(이름), 새 프로젝트, 가져오기(`design.json`), 삭제(⋯ 메뉴에서 프로젝트 이름을 입력해 확인. DB에서만 지우고 내보낸 문서 폴더는 그대로 둔다) |
| 상단 | Colab처럼 바로 바꿀 수 있는 프로젝트 이름, 저장 상태(`저장됨 · 방금`), 위치 경로, `검사 N`, 내보내기 |
| 가운데 캔버스 | 점 격자 위의 카드 그래프. 기본 화면은 에이전트 지도이고, 에이전트 카드를 두 번 누르면 그 내부 단계로 들어간다. 위에 떠 있는 도구 캡슐(노드 추가, 자동 정렬, 프로젝트 문서, 도구 목록, 데이터 사전), 왼쪽 아래 확대·축소·화면 맞춤·간단히/자세히, 아래 가운데 되돌리기·다시 실행 |
| 오른쪽 사이드바 | `[문서] [검토]` 탭. 문서 탭은 클릭한 노드나 연결의 템플릿 섹션별 입력칸과 md 미리보기, 검토 탭은 검토 챗봇과의 대화. 왼쪽 경계를 끌어 폭을 바꾸고, 그 폭은 브라우저에 기억된다 |

- 노드는 둥근 카드, 연결은 화살표다. 흐름은 왼쪽에서 오른쪽으로 놓인다(내보내는 문서의 Mermaid는 위에서 아래).
- **카드는 위에서 아래로 읽는다: input → 과정 → output → 다음.** 상세 내용은 문서에만 쓴다.
  - 에이전트 카드: 번호 배지·이름(두 줄까지), `단계 N`·`⚠ N`(검사 문제가 있을 때) 칩, 역할, input(들어오는 연결이 나르는 데이터), output(나가는 연결이 나르는 데이터), 다음 행(나가는 연결마다 `도착 · 데이터`, 조건 연결은 `조건 → 도착 · 데이터`, 없으면 `연결 없음`).
  - 단계 카드: 번호 배지·이름, 유형 아이콘(판단 ◇, 처리 □, 외부 연동 ⇄, 사람 확인 ◉)·`⚠ N` 칩, 요약, input, 과정(`과정 3  조건 확인 → 장소 선정 → 초안 생성`), output, 다음 행, 도구 칩(종류 아이콘).
  - 시작과 끝은 알약 모양이다. 시작은 나가는 연결이 둘 이상이면 행을 갖는다. 에이전트 안에도 시작과 끝이 있다.
- 연결선은 다음 행 오른쪽의 점(포트)에서 나가고, 선 위에는 글자를 쓰지 않는다. 그래서 연결이 많아도 글자가 겹치지 않는다.
- **포트를 끌어 연결한다.** 점을 끌어 다른 카드에 놓으면 연결이 생긴다. 다음 행에서 끌면 그 연결의 도착지가 바뀌고, 카드 머리의 점에서 끌면 새 연결이 생긴다. 한 카드에서 나가는 연결이 둘이 되면 모두 조건 연결로 바뀌고, 새 연결의 조건 칸이 열린다. Esc로 취소한다.
- 행을 누르면 그 연결의 문서, input·과정·output·도구 줄을 누르면 그 칸이 바로 열린다. 카드에 마우스를 올리면 살짝 떠오르고, 단계 카드는 input과 output 데이터를 짧게 보여 준다. 행에 올리면 그 선이, 선에 올리면 양 끝 카드가 강조된다.
- **간단히/자세히 보기**: 간단히는 머리와 다음 행만 남긴다. 큰 그래프를 볼 때 쓰고, 브라우저에 기억된다.
- 예전 배치(위→아래)로 저장된 프로젝트는 처음 열 때 한 번 자동으로 다시 정렬한다(되돌리기 가능). 카드가 커져 아래 카드와 겹치면 아래 카드를 밀어낸다.
- 연결선은 카드 아래로 지나간다. 앞으로 가는 연결은 모서리가 둥근 꺾은선, 되돌아가는 연결은 점선 곡선이다.
- 에이전트마다 색을 자동으로 정하고 사용자가 바꿀 수 있다. 기본 8색은 흰 글자와의 대비가 4.5:1 이상이고, 배지 글자색은 색의 밝기에 따라 흰색이나 검은색으로 정해진다. 내부 단계 카드는 소속 에이전트의 색을 따른다.
- 카드나 연결선을 누르면 문서 탭이 열린다. 빈 곳을 눌러도 마지막으로 연 문서와 선택은 그대로 남는다. 검토가 필요하면 검토 탭을 누른다. 에이전트가 없는 프로젝트를 처음 열 때는 요구사항 인터뷰를 위해 검토 탭이 열린다.
- AI가 답하면 검토 탭에 새 메시지 표시가 붙는다. 입력 중인 흐름이 끊기지 않도록 탭은 저절로 바뀌지 않는다.
- 제안 카드에 마우스를 올리면 바뀌는 노드와 연결이 캔버스에 강조된다.
- 그래프 조작은 이동, 확대와 축소, 포트를 끌어 연결하기, 자동 정렬, 화면 맞춤이다. AI가 그린 초안은 자동 정렬로 배치된다. 편집할 때는 화면 위치가 그대로 유지된다.
- **자동 정렬**(`assets/web/layout.js`, 직접 작성한 층 배치): 카드의 어느 다음 행에서 선이 나가는지를 알고 배치한다.
  - 시작은 맨 왼쪽 열, 끝은 맨 오른쪽 열에 둔다. 열은 시작에서 가장 먼 거리(최장 경로)로 정하고, 들어오는 연결이 없는 카드는 첫 열이 아니라 이어지는 카드 바로 앞 열에 둔다.
  - 되돌아가는 연결은 시작에서 다음 행 순서로 따라가며 찾고(깊이 우선), 열 계산에서 빼 점선 곡선으로 그린다.
  - 열을 둘 이상 건너뛰는 연결에는 지나가는 열마다 좁은 길(빈 자리)을 남기고, 그 선은 도착 카드 바로 앞에서 꺾여 길을 따라 카드 사이로 지나간다.
  - 위아래 위치는 열마다 "이어진 다음 행의 높이"(중앙값)에 카드의 입력 점을 맞추려 하고, 겹치지 않는 가장 가까운 자리를 계산한다(최소 제곱, 인접 위반 묶기). 좌→우, 우→좌로 번갈아 12번 맞춘 뒤 좌→우로 한 번 더 맞춰, 한 줄로 이어지는 흐름은 곧은 선이 된다. 같은 열의 순서는 이어진 다음 행의 높이 순서라 선이 덜 엇갈린다.
  - 연결이 하나도 없는 카드는 그래프 아래 한 줄에 문서 순서대로 놓는다.
  - 한 카드에서 나가는 선들은 꺾이는 위치를 조금씩 다르게 해(아래로 가면 위 행이 더 늦게 꺾임) 세로선이 겹치지 않는다.
  - AI가 일부 카드만 더하면 전체를 다시 배치하지 않고, 새 카드만 이어진 카드 옆(다음 행 높이에 맞춰)의 빈자리에 놓는다. 위치 없는 카드가 절반을 넘으면 전체를 정렬한다.
  - 빈자리 찾기는 위아래를 옆보다 먼저 살펴 카드가 제 열에 머물게 한다.
- **만들기와 배치**
  - 빈 곳을 두 번 누르면 그 자리에 빠른 추가 메뉴가 뜬다. 도구 캡슐의 추가는 보이는 화면 가운데에 만든다. 새 카드는 20px 격자에 맞추고, 다른 카드와 겹치면 가까운 빈자리로 옮긴다.
  - 포트를 누르면 오른쪽에 이어진 다음 카드가 생긴다. 포트를 끌어 빈 곳에 놓으면 그 자리에 카드를 만들고 잇는다.
  - 카드를 끌어 놓으면 격자에 맞춘다(Alt를 누르면 맞추지 않음). 화살표 키로 1칸, Shift+화살표로 5칸 옮긴다.
- **오른쪽 클릭 메뉴**: 빈 곳(여기에 추가, 자동 정렬, 화면 맞춤), 카드(이름 바꾸기, 들어가기, 다음 추가, 연결할 곳 고르기, 복제, 삭제), 연결선(조건·항상 연결 바꾸기, 중간에 넣기, 삭제). 화살표·Enter·Esc로 고르고, Shift+F10이나 메뉴 키로 선택한 것의 메뉴를 연다.
- **여러 개 선택**: Shift를 누른 채 끌면 여러 카드를 고른다. 한 번에 지우고 한 번에 되돌린다.
- 복제(⌘D)는 내용을 그대로 두고 새 번호를 준다. Enter나 F2는 문서 패널의 이름 칸으로 간다(글자 선택됨).
- **찾기(⌘K)**: 이름이나 번호로 노드를 찾아 그곳으로 간다.
- 추가·삭제·복제 뒤에는 아래에 알림이 뜨고, 알림의 `되돌리기`로 바로 취소한다.
- `?`를 누르면 단축키 목록이 열린다.
- 카드는 글자 폭을 재서 줄 수를 정하고 그만큼 높이를 잡는다. 두 줄을 넘는 이름은 말줄임표로 줄이고 전체 이름은 마우스를 올리거나 문서 패널에서 본다.
- 문서 패널은 필수 항목을 위에 모으고, 선택 항목은 비어 있으면 "선택 항목 N개"로 접어 둔다.
- 빈 캔버스에는 첫 에이전트(또는 단계)를 추가하거나 AI와 인터뷰를 시작하는 안내가 뜬다. 프로젝트 목록에는 마지막 수정 시각이 함께 보인다.
- 키보드: 캔버스에서 `+`·`-`로 확대·축소, `0`으로 화면 맞춤, ⌘K 찾기, ⌘D 복제, Enter·F2 이름 바꾸기, Delete 삭제, 화살표 이동, `?` 단축키 목록. 한 글자 단축키는 캔버스에 포커스가 있을 때만 동작하고, 버튼에 포커스가 있으면 Enter와 Delete는 원래 뜻대로 동작한다.
- 키보드로 연결: 카드 메뉴의 `연결할 곳 고르기…`에서 이어질 카드를 고른다.
- 대화상자는 Tab이 안에서만 돌고, 닫으면 포커스가 연 곳으로 돌아간다. 삭제 확인은 `취소`에 포커스가 있다.
- 지운 연결이나 에이전트를 가리키던 "한도를 넘으면 갈 연결"과 내부 에이전트 도구는 함께 비운다. 나중에 같은 번호가 다시 생겨도 엉뚱한 곳을 가리키지 않는다.
- 알림의 `되돌리기`는 그 알림의 동작만 되돌린다. 그 뒤에 다른 편집을 하면 버튼이 사라진다.
- 화면은 애플식 시스템 서체와 토큰(라이트·다크)으로 그린다. 글자 대비는 본문 16.8:1, 보조 글자 5.07:1, 강조 링크 5.57:1(라이트 기준)이다. 움직임 줄이기, 투명도 줄이기, 대비 높이기 설정을 따른다.
- 되돌리기(⌘Z, Windows는 Ctrl+Z)와 다시 실행(⇧⌘Z)으로 최근 100단계를 오간다. 노드 추가·삭제·이동, 입력, 정렬, AI가 바꾼 내용, 적용한 제안 카드가 모두 포함된다. 같은 칸에 이어서 입력한 것은 한 단계로 묶이고, 입력칸 안의 ⌘Z는 글자 되돌리기다.
- `검사 N`은 저장할 때마다 내보내기 전 검사를 다시 돌린 결과다. 누르면 목록이 열리고, 항목을 누르면 그 노드로 간다.
- 문서 패널의 칸에는 무엇을 쓸지 안내 문구가 들어 있다. 단계 유형에 따라 필수 칸이 바뀐다(판단: 판단 기준, AI 지시, 실패 처리 / 외부 연동·사람 확인: 실패 처리).
- 문서 패널의 **과정** 편집: 행마다 번호, 단위, 이름, 하는 일, 행의 input → output, 도구를 적고 행 사이를 화살표로 잇는다. `+ 과정 추가`로 행을 늘리고 ↑ ↓로 순서를 바꾼다.
- 문서 패널의 **도구**: 단계는 도구 목록에서 칩으로 고르고, `새 도구 만들기…`로 바로 목록에 추가한다. 도구 목록은 종류, 이름(내부 에이전트면 에이전트 선택), 용도, 위치·접속, 대안과 쓰는 곳을 보여 준다.
- 문서 패널의 **데이터 사전**: 데이터마다 이름, 뜻, 필드(이름, 형식, 필수, 설명, 예)를 적는다. 설계에 나오지만 사전에 없는 데이터는 위에 모아 보여 주고 `모두 추가`로 한 번에 올린다. 내부 에이전트 도구의 이름은 그 에이전트 이름을 따른다.
- UI는 꼭 필요한 것만 둔다. 기능의 로직과 단계의 품질이 먼저이고, 나머지 UI는 필요해질 때 더한다.

## 6. 그래프 모델

- 깊이는 두 단계로 고정한다: 프로젝트 → 에이전트 → 단계. 에이전트 안에 에이전트를 넣지 않는다.
- 에이전트 사이의 연결은 에이전트 단위 그래프에만 둔다.
- 에이전트 안에는 시작과 끝을 둔다. 에이전트가 끝난 뒤 어디로 갈지는 에이전트 사이 연결의 조건이 정한다. 예: A1 → A2(검증 통과), A1 → A3(검증 실패).
- 에이전트가 하나뿐인 프로젝트도 같은 구조를 쓴다.

| 대상 | 번호 |
|---|---|
| 에이전트 | A1, A2 … |
| 에이전트 사이 연결 | L1, L2 … |
| 단계 | A1-N1, A1-N2 … |
| 에이전트 안의 연결 | A1-L1, A1-L2 … |

- 번호는 시작점부터 흐름 순서대로 매긴다.
- 되돌아가는 연결(반복)에는 최대 반복 횟수와 한도를 넘으면 갈 연결이 있어야 한다. 예: 최대 2번 되돌아오고, 넘으면 A2-L5로 간다.
- 단계마다 유형 하나를 붙인다: `판단`, `처리`, `외부 연동`, `사람 확인`.

## 7. 검토 챗봇

- 플러그인을 실행한 AI 세션의 서브에이전트가 맡는다. 서브에이전트를 읽지 못하는 Codex에서는 같은 세션이 같은 기준으로 직접 검토한다.
- 별도 터미널 세션은 쓰지 않는다. 한 프로젝트에는 대기하는 세션이 하나만 붙고, 나중에 실행한 세션이 이어받는다.
- 현재 설계의 주의점, 보완할 점, 개선할 점을 객관적으로 평가한다. 불필요한 과정을 줄이는 방향으로 제안하고, 억지 개선은 하지 않는다.
- 권한
  - 처음 초안은 AI가 직접 그린다.
  - 이후 개선안은 제안 카드로 낸다. 무엇을 왜 바꾸는지와 바뀌는 노드·연결을 보여 주고, 사용자가 "적용"을 눌러야 반영된다.
  - 사용자는 언제든 직접 고칠 수 있다.
- 적용한 제안은 프로젝트 문서의 "설계 결정"에 자동으로 한 줄 남는다. 거절한 제안은 문서에 남기지 않는다.

### 웹 메시지 대기

웹을 연 그 세션이 대기하며 메시지를 받는다. 네 호스트 모두 같은 대기 스크립트를 쓴다.

| 호스트 | 방식 |
|---|---|
| Claude Code | Monitor로 대기 스크립트를 `--stream`으로 실행한다. 메시지가 오거나 탭이 닫힐 때만 한 줄이 출력되어 AI가 깨어난다(시간 초과 줄은 내지 않는다). 터미널이 묶이지 않고, 30분마다 다시 건다 |
| Grok Build, Codex | 대기 스크립트가 메시지가 오거나 110초가 지나면 돌아온다. AI는 답하고 다시 실행한다. Grok 기본 명령 제한 120초 안이고, Codex는 150초 명령을 끊지 않았다 |
| Cursor | 같은 반복이고 대기 시간은 55초다. 명령 제한을 확인하지 못해 안전한 값으로 둔다 |

- 대기에는 시간 제한이 없다. 사용자가 편집만 하고 오래 말이 없어도, 탭이 닫히거나(`closed`) 다른 세션이 이어받을(`replaced`) 때까지 계속 기다린다. 그동안 Claude Code는 30분마다 대기를 다시 걸고, Codex·Grok은 약 2분, Cursor는 약 1분마다 짧은 호출이 하나씩 생긴다.
- AI 세션이 끝난 상태에서 보낸 메시지는 SQLite에 쌓였다가, 터미널에서 같은 명령을 다시 실행하면 차례대로 처리된다. 편집과 자동 저장은 AI와 상관없이 동작한다. 서버의 수명은 브라우저 탭에 묶여 있다.
- AI의 채팅 답은 마크다운 없이 평범한 문장으로 쓴다. 채팅 창은 마크다운을 그리지 않는다.
- 탭을 모두 닫으면 대기 스크립트가 "closed"를 돌려주고, AI가 마무리 보고를 한다.
- 대기 스크립트의 출력은 짧은 JSON 한 줄이다(Grok 출력 제한 20KB).

### 평가 기준

위에 있을수록 먼저 본다.

| 순위 | 기준 | 보는 것 |
|---|---|---|
| 1 | 구조 정합 | 아래 내보내기 전 검사 항목. 스크립트가 찾고, 챗봇은 왜 문제인지와 고치는 방법을 설명한다 |
| 2 | 의도 부합 | 설계가 요구사항과 성공 기준을 달성하는가. 검증 시나리오가 성공 기준을 모두 확인하는가 |
| 3 | 구현 가능성 | 구현하는 사람이나 AI가 묻지 않고 만들 수 있는가. 구현 준비 점검표 9개(데이터 구조, 과정 행의 input → output, 판단 기준과 AI 지시, 위치·접속과 실패 처리, 판별할 수 있는 조건과 완료 기준, 반복 한도, 시나리오)를 단계마다 본다 |
| 4 | 불필요한 과정 | 합쳐도 되는 단계, 판단 없이 전달만 하는 단계, 같은 일을 하는 두 단계, 역할이 겹치는 에이전트 |
| 5 | 분기 품질 | 조건을 데이터로 판별할 수 있는가. 규칙으로 될 일을 AI 판단으로 맡기지 않았는가. 실패 경로가 빠지지 않았는가 |
| 6 | 위험과 제약 | 결제, 발송, 삭제처럼 되돌리기 어려운 동작 앞에 사람 확인이 있는가. 제약을 어기는 흐름이 있는가 |
| 7 | 문서 명확성 | 판별할 수 없는 말이 있는가. 구현 이름이 과정의 이름과 도구의 위치 밖으로 새지 않았는가. 뜻이 같은데 이름이 다른 데이터가 있는가 |

### 제안 규칙

- 근거 필수: 제안마다 걸리는 기준, 대상 번호, 고치지 않으면 무엇이 깨지는지를 적는다. 근거를 댈 수 없으면 제안하지 않는다.
- 억지 개선 금지: 문제가 없으면 "문제 없음"이라고만 답한다. 취향 차이와 문장 다듬기는 제안하지 않는다. 문장은 한국어 다듬기 단계가 맡는다.
- 중요한 것부터 낸다. 사소한 것 여러 개는 카드 하나로 묶는다.
- 카드 형식: 제목, 근거(기준·대상 번호), 바꿀 것(추가·삭제·수정 목록), 효과, [적용] 버튼.
- 검토 시점: 상세 설계가 끝난 뒤, 사용자가 요청할 때. 에이전트 구성은 사용자가 역할 나누기를 직접 확인한다. 평소 질문에는 답만 하고, 관련이 있을 때만 제안한다.
- 검토 카드는 한 번에 한 장(바꾼 문서 전체를 담는다)이다. 한 장이 적용되거나 문서가 바뀌면 남은 카드는 낡아 적용되지 않는다.

### 내보내기 전 검사

아래 중 하나라도 걸리면 내보내지 않고 해당 위치를 표시한다. 검토 챗봇도 같은 항목을 평가의 근거로 쓴다.

- 단계의 output을 아무도 쓰지 않거나, input을 앞에서 아무도 만들지 않는다.
- 같은 곳에서 나가는 연결이 여럿인데 조건 연결이 아니거나, 조건 연결이 하나뿐이다.
- 에이전트 안에서 끝으로 가는 연결이 없거나, 막다른 단계, 시작에서 닿을 수 없는 단계가 있다.
- 과정이 비었거나, 이름이 있는 과정 행에 하는 일이 없다.
- 단계 유형에 필요한 칸이 비었다(판단: 판단 기준, AI 지시, 실패 처리 / 외부 연동·사람 확인: 실패 처리). 예시가 없다.
- 단계나 과정이 쓰는 도구가 도구 목록에 없거나, 목록의 도구를 아무 단계도 쓰지 않거나, 내부 에이전트 도구가 없는 에이전트를 가리킨다.
- 되돌아가는 연결에 최대 반복 횟수(숫자)와 한도를 넘으면 갈 연결(같은 곳에서 나가는 다른 연결)이 없다.
- 데이터 사전에 없는 데이터가 쓰였거나, 데이터에 필드(이름과 형식)가 없거나, 비슷한 이름이 두 개 있다(예: 여행 조건 / 여행 요구사항).
- 필수 칸이 비어 있다.

장황함이나 불필요한 내용, 판별할 수 없는 말은 검사로 막지 않고 검토 챗봇이 판단해 제안한다.

```text
│   └── edges/A1-L1_<연결_이름>.md
└── design.json                     # 다시 가져오기용 전체 구조(좌표·색 포함). 사람이 읽는 문서가 아니다
```

- 파일 이름은 `번호_이름.md`이고, 이름의 공백은 `_`로 바꾼다(40자까지). 공백이 있으면 md 링크가 깨진다.
- 연결 이름은 조건 연결이면 조건 요약(예: 후보 부족), 항상 연결이면 도착 이름이다. Mermaid의 연결 라벨과 같다.
- 루트(에이전트 폴더 + `edges/`)와 에이전트 폴더(`steps/` + `edges/`)는 같은 모양이다.

### 공통 규칙

- **목표는 바로 구현할 수 있는 문서다.** 칸마다 무엇을 얼마나 구체적으로 쓰는지는 `references/templates.md`가 정하고, 끝났는지는 그 안의 구현 준비 점검표로 판단한다.
- **구조는 고정한다.** 섹션 이름과 순서, 필수와 선택, 표의 칸, 번호와 링크 형식은 모든 프로젝트에서 같다.
- 글자 수 제한은 두지 않는다. 같은 사실은 한 곳에만 쓰고, 꾸밈말과 일반론은 쓰지 않는다. 선택 섹션이 비면 섹션째 생략한다.
- 제목: H1은 `번호 · 이름`이다(번호가 없는 프로젝트 README, GLOSSARY, CHANGELOG는 이름만). H2는 고정 섹션이다(GLOSSARY는 데이터마다 H2).
- 데이터가 나오는 표에는 데이터 사전의 구조(`필드: 형식`)를 함께 보여 준다. 단계 문서만 열어도 데이터 모양을 알 수 있다.
- 링크는 `[A1-N2 질문 생성](…)`처럼 번호와 이름을 함께 쓴다.
- Mermaid는 README 파일에만 파일당 하나 둔다. 방향은 위에서 아래(TD)다. 시작은 `([시작])`, 끝은 `((끝))`이다.
- 구현 이름(파일, 모듈, 클래스, 함수, 주소)은 과정의 이름과 도구의 위치·접속에만 쓴다.

## 9. 저장, 내보내기, 가져오기

- **자동 저장**: 노드와 연결의 이동·추가·삭제, 사이드바 입력값, 프로젝트 이름, 적용한 제안 카드를 즉시 SQLite에 저장한다. 연속 입력은 잠깐 모아서 한 번에 저장한다. 저장 버튼은 없다.
- **원본은 하나**: 편집기의 데이터(SQLite)가 유일한 원본이다. md 문서는 내보낼 때마다 새로 생성하므로, md를 손으로 고친 내용은 다음 내보내기 때 사라진다. 수정은 편집기에서 한다.
- **수정 경로**: 웹과 AI 모두 로컬 서버를 거쳐서만 그래프를 고친다. 서버는 버전을 확인해 충돌을 막고, 변경을 화면에 바로 반영한다.
- **내보내기**: "내보내기" 버튼을 눌렀을 때만 한다.
  1. 내보내기 전 검사를 한다(7절).
  2. 한국어 다듬기: 설치된 clonamic-korean의 규칙 파일을 읽어 모든 문장 칸을 다듬는다. 결과는 제안 카드 하나(변경 N건, 바뀐 곳 비교)로 나오고, 적용하면 SQLite에 반영된다. 사실, 번호, 데이터와 필드 이름, 과정의 이름은 바꾸지 않는다.
  3. 스크립트가 템플릿에 데이터를 채워 문서를 만든다. 같은 데이터면 언제나 같은 문서가 나온다.
- **저장 경로**: 프로젝트마다 처음 내보낼 때 내보내기 창의 경로 입력칸에서 정한다. 추천 경로 `~/Documents/clonamic-agents/<프로젝트명>`이 미리 채워져 있고 고칠 수 있다. 브라우저는 폴더 선택 창으로 경로 문자열을 넘겨주지 못하므로 입력칸을 쓴다.
  - 서버가 폴더가 있는지, 쓸 수 있는지 확인한다. 이 도구가 만들지 않은 파일이 폴더에 있으면 "이 파일은 건드리지 않음"이라고 알린다.
  - 정한 경로는 SQLite에 문자열로 저장하고, 바꾸지 않으면 다음에도 그 경로에 저장한다. 내보내기는 AI 대기 상태와 상관없이 웹 안에서 끝난다.
- **다시 내보내기**: 폴더를 통째로 다시 쓰되, 도구가 만든 파일만 교체하거나 지운다. 사용자가 같은 폴더에 둔 다른 파일은 건드리지 않는다.
  - 도구가 만든 파일 목록은 이전 `design.json`에서 읽는다. 그 파일은 고쳐졌거나 다른 곳에서 왔을 수 있으므로, 폴더 밖을 가리키는 항목(`..`, 절대 경로)은 버린다.
  - 저장 경로는 사용자가 정하므로 홈 아래 어느 폴더든 쓸 수 있다. 막는 곳은 홈 폴더 자체, 그 위의 폴더, 최상위 폴더, 편집기 데이터 폴더다. 이 도구가 만들지 않은 같은 이름의 파일이 있으면 덮어쓰지 않고 멈춘다.
- **가져오기**: 내보낸 폴더의 `design.json`으로 다른 PC나 다른 곳에서 프로젝트를 그대로 가져와 추가할 수 있다.

## 10. 동작 구조

### 수명주기: 화면 = 수명

| 시점 | 동작 |
|---|---|
| 시작 | 스크립트 하나가 준비를 확인하고, 편집기 서버가 떠 있으면 다시 쓰고, 없으면 빈 포트로 띄운 뒤 브라우저를 연다. AI는 대기에 들어간다 |
| 작업 중 | 편집할 때마다 자동 저장된다. 채팅 메시지가 오면 AI가 깨어나 답한다 |
| 종료 | 브라우저 탭을 모두 닫으면 서버가 마지막 저장을 마치고 스스로 꺼진다. AI의 대기도 풀리고, AI가 짧게 마무리 보고를 한다 |
| 비정상 종료 | 터미널을 중단하거나 PC가 꺼져도 데이터는 이미 저장되어 있다. 다음 실행 때 이어간다 |

### 서버와 저장 위치

- 서버는 Python 3.12 표준 라이브러리(http.server, sqlite3)만 쓴다. 따로 설치할 의존성이 없다.
- 포트는 23232부터 확인하고, 쓰이고 있으면 1씩 올려 빈 포트를 찾는다. 이미 떠 있는 서버가 이 편집기인지 확인해서 다시 쓴다.
- 서버는 `127.0.0.1`에서만 열어 외부 접속을 막는다.
- 데이터(DB, 설정, 프로젝트별 저장 경로)는 `~/.clonamic/create-agent/`에 둔다. 어느 호스트에서 열어도 같은 프로젝트 목록이 보인다.
- 웹페이지(HTML, CSS, JS)는 미리 만들어 플러그인 설치 폴더에 두고 그곳에서 바로 서비스한다. 복사하지 않으므로, 플러그인을 업데이트하면 페이지도 함께 바뀐다.

### 실제 설치 환경 기준

모든 경로, 설치 확인, 저장 위치는 이 플러그인을 설치해서 쓰는 사람의 PC를 기준으로 한다. 제작 저장소를 기준으로 하지 않는다.

1. `~`는 실행하는 사람의 홈 폴더로 해석한다. 고정 경로를 쓰지 않으며, macOS, Linux, Windows가 같은 코드로 동작한다.
2. 웹페이지와 스크립트는 스크립트 자기 위치를 기준으로 찾는다. 플러그인 설치 위치를 미리 가정하지 않는다.
3. clonamic-korean은 사용자 PC에 설치된 위치에서 찾는다. 없으면 그 호스트의 방식으로 설치한다.
4. `~/.clonamic/create-agent/`는 처음 실행할 때 만들고 한 줄로 알린다. Python이 3.12보다 낮으면 설치 방법을 안내한다(`uv python install 3.12` 또는 OS 패키지 관리자).
5. `tests/`와 제작용 메모는 배포물에 넣지 않는다.
6. 서버는 사용자 PC의 `127.0.0.1`에서만 연다.
7. 검증은 임시 홈 폴더에 실제로 설치한 상태에서 한다. 사용자의 실제 `~/.claude`, `~/.clonamic`은 건드리지 않는다.

### clonamic-korean 설치

| 호스트 | 확인 | 없을 때 |
|---|---|---|
| Claude Code | Claude 매니페스트의 `"dependencies": ["clonamic-korean"]` | 이 플러그인을 설치할 때 함께 자동 설치된다 |
| Codex | 찾기 스크립트 | `codex plugin marketplace add clonamic/plugin` 다음 `codex plugin add clonamic-korean@clonamic`을 자동 실행하고 한 줄로 알린다 |
| Grok Build | 찾기 스크립트 | `grok plugin install https://github.com/clonamic/plugin#clonamic-korean --trust` 다음 `grok plugin enable clonamic-korean`을 자동 실행하고 한 줄로 알린다 |
| Cursor | 찾기 스크립트(`~/.cursor/plugins/local/clonamic-korean/`) | CLI에 설치 명령이 없어, clonamic-task-log와 같은 방식으로 저장소를 내려받아 `~/.cursor/plugins/local/`에 복사한다 |

- 찾기 스크립트는 네 호스트의 설치 경로를 차례로 확인하고, 처음 찾은 `SKILL.md`와 `references/`를 쓴다.

### 설치

```text
/plugin marketplace add clonamic/plugin
/plugin install clonamic-create-agent@clonamic
```

- Claude Code는 clonamic-korean을 함께 설치한다. Codex는 `codex plugin marketplace add clonamic/plugin` 다음 `codex plugin add clonamic-create-agent@clonamic`, Grok Build는 `grok plugin install https://github.com/clonamic/plugin#clonamic-create-agent --trust`로 설치한다.

### 제거

- 플러그인을 제거한 뒤 `~/.clonamic/create-agent/` 폴더를 지우면 남는 것이 없다. 내보낸 문서는 사용자가 정한 폴더에 그대로 남는다.

| 일부만 새로 생긴 카드는 그 자리만 배치 | AI가 단계 하나를 더할 때마다 사용자가 옮긴 배치가 통째로 바뀌면 안 된다 | 위치 없는 카드가 하나라도 있으면 전체 재정렬 |
| 문서 모양은 서버 입구에서 검사 | `put`, 제안 카드, 가져오기로 들어온 문서의 칸 형식과 번호가 틀리면 이후 검사·문서 생성·편집기가 모두 멈춘다. 들어올 때 거절하면 AI가 바로 고칠 수 있다 | 읽을 때마다 방어 코드 |
| 편집기 서버는 다른 사이트의 요청을 거절 | 대기(`/api/wait`)는 메시지를 가져가므로 쓰기처럼 CLI 머리글을 요구하고, 브라우저가 붙이는 `Sec-Fetch-Site: cross-site` 요청은 모두 거절한다 | Host 검사만 |
| 프로젝트 삭제만 추가 | 테스트 프로젝트가 쌓인다. 복제는 내보내기 → 가져오기로 된다 | 삭제 + 복제, 넣지 않음 |

## 13. 구현 중 확인한 것

| 항목 | 결과 | 근거 |
|---|---|---|
| Claude 매니페스트의 `dependencies` | 통과 | `claude plugin validate` 통과. 임시 홈 폴더에 설치하면 clonamic-korean이 함께 설치된다(`+ 1 dependency`) |
| Codex와 Grok의 clonamic-korean 설치 | 셸 명령으로 동작 | 임시 홈 폴더에서 `codex plugin add`, `grok plugin install --trust`가 묻는 창 없이 설치를 마쳤다. 네 호스트의 설치 위치 모두에서 찾기 스크립트가 clonamic-korean을 찾았다 |
