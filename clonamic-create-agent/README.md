# clonamic-create-agent

## 핵심 요약

- 사용자와 AI가 대화하며 에이전트 파이프라인을 노드와 연결의 그래프로 설계하고, 구현 방식에 묶이지 않는 한국어 설계 문서로 정리하는 플러그인이다.
- 명령은 `/clonamic-create-agent [프로젝트명 또는 만들고 싶은 것]` 하나이고, 사용자가 직접 입력했을 때만 실행된다.
- 실행하면 로컬 웹 편집기가 열린다. 캔버스에서 그래프를 보고 고치고, 오른쪽 패널에서 칸을 채우며, 검토 챗봇이 설계를 평가해 제안한다.
- 목표는 구현하는 사람이나 AI가 내보낸 문서만 보고 바로 만들 수 있는 설계다. 코드는 만들지 않는다.

## 1. 문제와 목표

- AX 자동화는 여러 기능이 모여 하나의 파이프라인을 이룬다. 그래서 설계가 결과를 좌우한다.
- 설계에는 세 가지가 필요하다: 한눈에 보이는 흐름, 문서만으로 같은 파이프라인을 다시 만들 수 있는 재현성, 쉬운 수정.
- 파이프라인은 기능과 분기로 이루어지므로 노드와 연결(LangGraph의 사고방식)로 설계한다. 문서에는 LangGraph나 코드 용어를 쓰지 않는다.

| 구분 | 내용 |
|---|---|
| 하는 것 | 요구사항 확인, 에이전트와 단계의 그래프 설계, 상세 설계, 객관적 검토, 문서 완성 |
| 하지 않는 것 | 코드 생성, 실행, 테스트. 특정 프레임워크나 언어에 맞춘 문서 |
| 문서의 쓰임 | 사람이 직접 구현, 스킬·플러그인으로 구성, 웹·앱·Hermes·LangGraph 등으로 구현, AI에게 맡겨 구현 |

- 구현 이름(파일, 모듈, 클래스, 함수, 주소)은 **과정의 이름**과 **도구의 위치·접속**에만 쓰고, 나머지 칸은 쉬운 말로 쓴다.

## 2. 용어

| 용어 | 뜻 |
|---|---|
| AI | Claude Code, Codex, Grok Build, Cursor 같은 에이전트 도구 |
| 프로젝트 | 설계 하나. 파이프라인 하나다 |
| 에이전트 | 역할 하나를 맡는 큰 노드 |
| 단계 | 에이전트 안에서 그 역할을 이루는 노드 |
| 연결 | 노드를 잇는 간선. 항상 연결과 조건 연결이 있다 |
| input / output | 노드가 받는 데이터와 내놓는 데이터. 에이전트의 input/output은 연결이 나르는 데이터로 자동 계산된다 |
| 끝 | 흐름이 끝나는 곳. 에이전트 안의 끝은 그 에이전트가 일을 마친 것이고, 다음 에이전트는 에이전트 사이 연결의 조건이 정한다 |
| 과정 | 단계 안의 처리 순서. 파일·모듈·클래스·함수·외부 호출·사람 작업 단위로 한 행씩 쓴다 |
| 데이터 사전 | 데이터마다 필드(이름, 형식, 필수, 설명, 예)를 적는 곳. 구현할 때 그대로 데이터 구조가 된다 |
| 도구 목록 | 프로젝트가 쓰는 MCP 서버, 다른 에이전트, 파일·스크립트, 외부 API, 웹 검색, 데이터베이스, 모델. 단계와 과정은 번호(T1)로 가리킨다 |
| 제안 카드 | 검토 챗봇의 개선안. 사용자가 "적용"을 눌러야 반영된다 |

## 3. 사용 흐름

1. 사용자가 명령을 입력한다. 뒤에 만들고 싶은 것을 적으면 첫 요청으로 쓴다.
2. Python 3.12 이상, clonamic-korean(없으면 설치), 편집기 서버를 확인하고 브라우저에 편집기를 연다.
3. **요구사항 인터뷰**: 빈 칸만 한 번에 하나씩 추천 답과 함께 묻는다. 요구사항, input/output, 성공 기준, 제약, 사람 확인 지점, 쓸 수 있는 도구와 외부 시스템, 범위 밖.
4. **에이전트 구성**: AI가 에이전트와 그 사이 연결(조건, 전달 데이터)을 그리고, 사용자가 역할 나누기를 확인한다.
5. **상세 설계**: 에이전트마다 단계와 연결, 단계의 모든 칸, 데이터 사전의 필드, 도구의 위치·접속을 채운다. 정할 수 없는 값은 추천 값으로 채워 설계 결정에 남기고 에이전트마다 한 번에 확인받는다. 구현 준비 점검표로 빠진 곳을 채우고, 그 에이전트만 검토해 바로 고친 뒤 다음 에이전트로 간다.
6. **검토**: 검토 챗봇이 평가하고 제안 카드를 낸다.
7. **내보내기**: 검사 → 한국어 다듬기 → 문서 생성.
8. 브라우저 탭을 모두 닫으면 끝난다. 이미 있는 프로젝트는 저장된 상태에서 이어간다.

## 4. 편집기

| 위치 | 내용 |
|---|---|
| 왼쪽 | 프로젝트 목록, 새 프로젝트, 가져오기(`design.json`), 삭제(이름을 입력해 확인. 내보낸 문서는 남는다) |
| 상단 | 프로젝트 이름, 저장 상태, 위치 경로, `검사 N`(누르면 목록, 항목을 누르면 그곳으로), 내보내기 |
| 캔버스 | 에이전트 지도. 에이전트 카드를 두 번 누르면 그 안의 단계로 들어간다. 도구 막대(추가, 자동 정렬, 프로젝트 문서, 도구 목록, 데이터 사전), 확대·축소·화면 맞춤·간단히/자세히, 되돌리기·다시 실행 |
| 오른쪽 | `[문서] [검토]` 탭. 문서 탭은 선택한 노드나 연결의 칸과 md 미리보기, 검토 탭은 검토 챗봇과의 대화. 폭은 끌어서 바꾸고 기억된다 |

**카드와 연결**

- 카드는 위에서 아래로 읽는다: input → 과정 → output → 다음. 다음 행은 나가는 연결마다 `도착 · 데이터`, 조건 연결은 `조건 → 도착 · 데이터`다.
- 연결선은 다음 행 오른쪽의 점에서 나가고, 선 위에는 글자를 쓰지 않는다. 앞으로 가는 연결은 둥근 직각선, 되돌아가는 연결은 카드 위나 아래로 돌아가는 점선이다.
- 점을 끌어 다른 카드에 놓으면 연결이 생기고, 다음 행의 점을 끌면 도착지가 바뀐다. 한 카드에서 나가는 연결이 둘이 되면 모두 조건 연결로 바뀌고 조건 칸이 열린다.
- 행을 누르면 그 연결의 문서, input·과정·output·도구 줄을 누르면 그 칸이 열린다. 빈 곳을 눌러도 마지막 문서는 남는다.
- 에이전트마다 색이 정해지고 바꿀 수 있다. 단계 카드는 소속 에이전트의 색을 따른다.

**자동 정렬** (`assets/web/layout.js`)

- 시작은 맨 왼쪽, 끝은 맨 오른쪽 열에 둔다. 열은 시작에서 가장 먼 거리로 정하고, 되돌아가는 연결은 열 계산에서 뺀다.
- 카드의 입력 점을 이어진 다음 행의 높이에 맞추고 겹치지 않는 가장 가까운 자리를 계산한다. 한 줄로 이어지는 흐름은 곧은 선이 되고, 같은 열의 순서는 다음 행 순서를 따라 선이 덜 엇갈린다.
- 열을 건너뛰는 연결은 카드가 없는 높이로 지나간다. 한 카드에서 나가는 선들은 꺾이는 위치를 달리해 겹치지 않는다.
- AI가 카드 몇 개만 더하면 전체를 다시 배치하지 않고 새 카드만 이어진 카드 옆에 놓는다.

**만들기와 편집**

- 빈 곳 두 번 누르기, 오른쪽 클릭 메뉴, 점 누르기(오른쪽에 다음 카드), 점을 빈 곳에 놓기(만들고 연결)로 그 자리에 만든다. 새 카드는 격자에 맞추고 겹치면 빈자리로 옮긴다.
- 오른쪽 클릭 메뉴: 빈 곳(추가, 자동 정렬, 화면 맞춤), 카드(이름 바꾸기, 들어가기, 다음 추가, 연결할 곳 고르기, 복제, 삭제), 연결선(조건·항상 바꾸기, 중간에 넣기, 삭제).
- Shift를 누른 채 끌면 여러 카드를 고르고, 한 번에 지우고 되돌린다.
- 키보드: `+`·`-`·`0` 확대·축소·맞춤, ⌘K 찾기, ⌘D 복제, Enter·F2 이름, Delete 삭제, 화살표 이동, Shift+F10 메뉴, `?` 단축키 목록. 한 글자 단축키는 캔버스에 포커스가 있을 때만 동작한다.
- 되돌리기(⌘Z)와 다시 실행(⇧⌘Z)은 최근 100단계다. AI가 바꾼 내용과 적용한 제안 카드도 포함된다. 추가·삭제 뒤의 알림에서도 그 동작만 되돌린다.

**문서 패널**

- 필수 칸이 위에 오고, 비어 있는 선택 칸은 접힌다. 칸마다 무엇을 쓸지 안내 문구가 있다.
- 단계 유형에 따라 필수 칸이 바뀐다: 판단은 판단 기준, AI 지시, 실패 처리 / 외부 연동·사람 확인은 실패 처리.
- 과정은 행마다 단위, 이름, 하는 일, input → output, 도구를 적는다.
- 도구는 목록에서 고르거나 바로 새로 만든다. 데이터 사전은 데이터마다 필드를 적고, 설계에 나오지만 사전에 없는 데이터를 한 번에 추가한다. 데이터 이름을 바꾸면 그 데이터를 쓰는 곳(input/output, 전달 데이터, 과정 행)이 함께 바뀐다.

## 5. 그래프 모델

- 깊이는 프로젝트 → 에이전트 → 단계로 고정한다.
- 에이전트 안에는 시작과 끝이 있다. 에이전트가 끝난 뒤 갈 곳은 에이전트 사이 연결의 조건이 정한다. 예: A1 → A2(검증 통과), A1 → A3(검증 실패).
- 같은 곳에서 나가는 연결이 둘 이상이면 모두 조건 연결이다. 되돌아가는 연결에는 최대 반복 횟수와 한도를 넘으면 갈 연결이 있어야 한다.
- 단계 유형: 판단(AI가 판단), 처리(정해진 규칙), 외부 연동, 사람 확인.

| 대상 | 번호 |
|---|---|
| 에이전트 / 에이전트 사이 연결 | A1 … / L1 … |
| 단계 / 에이전트 안의 연결 | A1-N1 … / A1-L1 … |
| 도구 | T1 … |

## 6. 검토와 검사

- 검토는 실행한 AI 세션의 서브에이전트가 맡는다(Codex는 같은 세션이 직접). 평가 기준과 제안 규칙은 `references/review.md`, 칸 기준과 구현 준비 점검표는 `references/templates.md`에 있다.
- 처음 그리는 것(에이전트 구성, 상세 설계)은 AI가 직접 하고, 그 뒤 개선은 제안 카드로만 낸다. 적용한 제안은 프로젝트 문서의 설계 결정에 남는다.
- 검토 카드는 바꾼 문서 전체를 담는다. 한 장이 적용되거나 문서가 바뀌면 남은 카드는 적용되지 않는다.

**내보내기 전 검사** (하나라도 걸리면 내보내지 않는다)

- output을 아무도 쓰지 않거나, input을 아무도 만들지 않는다.
- 같은 곳에서 나가는 연결이 여럿인데 조건 연결이 아니거나, 조건 연결이 하나뿐이다.
- 끝으로 가는 연결이 없거나, 막다른 단계나 시작에서 닿을 수 없는 단계가 있다.
- 과정이 비었거나 하는 일이 없는 과정 행이 있다. 유형에 필요한 칸이나 예시가 비었다.
- 도구가 목록에 없거나, 쓰이지 않거나, 없는 에이전트를 가리킨다.
- 되돌아가는 연결에 최대 반복 횟수(숫자)나 한도를 넘으면 갈 연결이 없다.
- 데이터가 데이터 사전에 없거나 필드가 없거나, 비슷한 이름이 둘 있다.
- 과정 행이 단계 input이나 앞 행 output에 없는 데이터를 쓰거나, 단계 output을 만드는 행이 없다.
- 판단 단계에 모델 도구가 없거나, 사람 확인 단계가 사람 확인 지점에 없다.
- 검증 시나리오의 경로에 없는 번호가 있다.
- 필수 칸이 비었다.

**웹 메시지 대기**

| 호스트 | 방식 |
|---|---|
| Claude Code | Monitor로 `wait --stream`을 건다. 메시지나 종료가 있을 때만 한 줄이 나와 AI가 깨어난다. 30분마다 다시 건다 |
| Grok Build, Codex | `wait`가 메시지가 오거나 110초가 지나면 돌아오고, AI가 다시 실행한다 |
| Cursor | 같은 방식, 55초 |

- 탭이 닫히거나(`closed`) 다른 세션이 이어받을(`replaced`) 때까지 시간 제한 없이 기다린다. AI가 없을 때 보낸 메시지는 쌓였다가 다음 실행 때 처리된다.

- 섹션 이름과 순서, 표의 칸, 번호와 링크는 스크립트가 고정해서 만든다. 같은 데이터면 언제나 같은 문서가 나온다. 비어 있는 선택 섹션은 생략한다.
- 데이터가 나오는 표에는 데이터 사전의 구조(`필드: 형식`)를 함께 보여 준다.

| 문서 | 섹션 |
|---|---|

## 8. 저장, 내보내기, 가져오기

- **자동 저장**: 편집할 때마다 SQLite에 저장한다. 편집기의 데이터가 유일한 원본이고, md 문서는 내보낼 때마다 새로 만든다.
- **수정 경로**: 웹과 AI 모두 로컬 서버를 거쳐서만 고친다. 서버는 버전으로 충돌을 막고, 들어오는 문서의 칸 형식과 번호를 검사한다.
- **내보내기**: 버튼을 눌렀을 때만 한다. 검사를 통과해야 하고, clonamic-korean으로 다듬기 카드를 받을 수 있다.
- **저장 경로**: 처음 내보낼 때 입력칸에서 정한다(추천 `~/Documents/clonamic-agents/<프로젝트명>`). 홈 폴더 자체, 최상위 폴더, 편집기 데이터 폴더에는 내보낼 수 없다.
- **다시 내보내기**: 이 도구가 만든 파일만 바꾸거나 지우고, 같은 폴더의 다른 파일은 그대로 둔다. 새 파일을 먼저 쓰고 옛 파일을 지운다.
- **가져오기**: 내보낸 `design.json`으로 다른 PC에서도 프로젝트를 그대로 가져온다.

## 9. 동작 구조

- 수명은 화면과 같다. 실행하면 서버가 떠 있으면 다시 쓰고 없으면 빈 포트(23232부터)로 띄운다. 탭을 모두 닫으면 서버가 스스로 꺼지고 AI가 짧게 마무리 보고를 한다.
- 서버는 Python 표준 라이브러리만 쓰고 `127.0.0.1`에서만 연다. 다른 사이트에서 오는 요청은 거절한다.
- 데이터는 `~/.clonamic/create-agent/`에 두어 어느 호스트에서 열어도 같은 목록이 보인다. 웹페이지는 플러그인 폴더에서 바로 서비스한다.
- 모든 경로는 실행하는 사람의 PC 기준이다. macOS, Linux, Windows가 같은 코드로 동작한다.

| 구성 | 내용 |
|---|---|
| 스킬 | `clonamic-create-agent`. 명시 호출만 한다 |
| 서브에이전트 | 검토 챗봇 `clonamic-agent-reviewer` |
| 스크립트 | 편집기 서버, 대기, 검사, 문서 생성, clonamic-korean 찾기 |
| 웹페이지 | HTML, CSS, JS, `layout.js`, Cytoscape.js |
| 참고 문서 | `references/format.md`(데이터 형식), `templates.md`(칸 기준과 점검표), `review.md`(검토 기준) |

## 10. 의존성과 설치

| 항목 | 내용 |
|---|---|
| Python | 3.12 이상, 표준 라이브러리만 |
| clonamic-korean | 필수. Claude Code는 의존성으로 함께 설치되고, Codex·Grok·Cursor는 찾기 스크립트가 없으면 설치한다. 설치하지 못하면 다듬기만 건너뛴다 |
| Cytoscape.js | 캔버스. MIT, 버전 고정, `THIRD_PARTY_NOTICES.md`에 고지 |
| 지원 호스트 | Claude Code, Codex, Cursor, Grok Build |

```text
/plugin marketplace add clonamic/plugin
/plugin install clonamic-create-agent@clonamic
```

- Codex: `codex plugin marketplace add clonamic/plugin` → `codex plugin add clonamic-create-agent@clonamic`
- Grok Build: `grok plugin install https://github.com/clonamic/plugin#clonamic-create-agent --trust`
- 제거: 플러그인을 지운 뒤 `~/.clonamic/create-agent/`를 지우면 남는 것이 없다. 내보낸 문서는 그대로 남는다.
