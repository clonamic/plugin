# 보고서

작업이 끝났거나 막혔을 때, 무엇이 됐고 무엇이 안 됐는지를 증거와 함께 한 번 알리는 문서다. 채팅에만 쓰고 파일로 만들지 않는다.

## 언제 쓰나

- 명세서로 승인받은 작업이 끝났을 때, 모든 완료 항목을 마지막 변경 뒤에 다시 확인하고 한 번 쓴다.
- 작업이 막혔을 때 막힘 보고로 한 번 쓴다. 남은 항목이 하나라도 있으면 완료 보고를 쓰지 않는다.
- 쓰지 않는다: 질문에 대한 답, 설명, 진행 중 상태 알림.

## 형식

```text
# 보고서

결과: 완료 N/N — 핵심 숫자나 원인 한 줄
미검증·실패: 없음

결과1 [완료1]: 완료 — 새로 확인한 증거
결과2 [완료2]: 미완 — 원인

적용·배포·백업: 범위에 있을 때만.
위험: 남은 실제 위험이 있을 때만.
다음 행동: 사용자만 할 수 있는 일이 있을 때만.
```

- 첫 줄은 결론이다. 모두 끝났으면 `결과: 완료 N/N`, 하나라도 남았으면 `결과: 막힘 n/N`과 원인을 쓴다.
- 미검증·실패를 결과 줄 바로 다음에 먼저 쓴다. 없으면 `미검증·실패: 없음`.
- 결과N은 작업명세서의 완료N에 대응한다. 판정은 완료, 미완, 미검증 중 하나이고, 뒤에 이번에 새로 확인한 증거(테스트 결과, diff, 원격 상태, 출력)를 붙인다. 변경 전에 확인한 것은 증거가 아니다.
- 적용·배포·백업, 위험, 다음 행동 줄은 해당할 때만 쓴다.
- 한 줄에 한 사실, 들여쓰기 없이 쓴다. 형용사보다 숫자를 쓴다. 식별자와 명령은 그대로 둔다.
- 한 줄 형식 개발명세서로 한 작업은 결과 줄과 증거 한 줄이면 된다.
- 쓰지 않는다: 도구 사용 과정, 요청 다시 말하기, 같은 결론 반복, "더 할까요?" 같은 제안.

## 예시

```text
# 보고서

결과: 완료 2/2 — 다크 모드 토글 추가, 재시작 뒤에도 유지
미검증·실패: 없음

결과1 [완료1]: 완료 — npm test 14/14 통과, 토글 클릭 시 data-theme=dark
결과2 [완료2]: 완료 — theme=dark 저장 뒤 재시작, 다크 유지 확인
```

## 보고 뒤 규칙

- 보고서는 작업마다 한 번이다. 같은 내용을 다시 보고하지 않는다.
- 사용자가 결과를 고치라고 하면, 요구가 같으면 승인된 경계 안의 재시도로 바로 고치고, 요구가 바뀌면 새 작업명세서를 쓴다.
- 막힘 보고 뒤 사용자가 막힌 원인을 풀면 같은 승인으로 이어서 끝까지 한다.
