# clonamic-task-log

## 핵심 요약

- 지금 열린 프로젝트에서 내가 그날 직접 한 git 작업을, 포트폴리오에 바로 옮길 수 있는 작업 기록으로 정리하는 플러그인이다.
- 명령은 `/clonamic-task-log [날짜]` 하나이고, 명시적으로 입력했을 때만 실행된다. 날짜를 생략하면 오늘이다.
- 기록은 커밋 통계가 아니라 그날 어떤 문제를 어떻게 진단하고 왜 그렇게 풀었으며 무엇이 달라졌는지를 쓴다. 프로젝트 밖의 사람이 읽어도 알 수 있게 쓰고, 포트폴리오 가치는 별도 절이 아니라 배경·접근·결과에 녹인다. 에이전트가 실제 변경을 읽고 쓴 작업 메모를 바탕으로 작성자 서브에이전트가 한국어로 쓴다.
- 결과는 `<프로젝트>/<에이전트 폴더>/log-part/`의 로컬 파일과 Notion `개인페이지 / project / <프로젝트명> / 작업로그` 아래 페이지다.
- 파일 이름, 경로, 커밋 해시, 비밀 정보와 통계 문장, 얼버무림은 게이트가 막는다. 게이트를 통과하지 않으면 저장도 동기화도 하지 않는다.

## 1.4.0에서 바뀐 것

실제 기록에서 나온 문제(같은 내용이 핵심 요약·한 일·기술 판단·오늘 변화에 네 번 나옴, 내부 용어와 규칙 나열, 성과 대신 시험 수로 채운 결과, 서로 다른 일을 억지로 묶은 항목, 명사형 종결)를 서식과 게이트에서 함께 고쳤다.

| 전 | 지금 |
|---|---|
| 절 `기술 판단` · `문제 해결` · `오늘 변화` | 없앴다(`removed-section`). 판단은 접근 첫 문장, 진행은 Notion 진행 현황, 문제 해결 사례는 한 일 항목에서 가져온다 |
| 접근 한 줄에 쉼표로 여러 변경 | 접근 아래 세부 줄 2~4개, 줄마다 사실 하나(`detail-count`). 선택 줄 `- 전후 —`로 바뀌기 전후 모습 |
| 끝난 일을 따로 정리하지 않음 | 마일스톤 칸이 새로 체크되거나 기능의 칸이 모두 체크되면 `prepare`의 `completions`(지난 기록 이력 포함)가 알려 주고 `## 완료 정리`(만든 것 · 거쳐 온 길 · 남은 한계)가 붙는다. 작업 메모의 `- 완료:` 줄도 같다 |
| 같은 검증 문장 반복 | 비슷한 문장이 다시 나오면 막는다(`duplicate-line`). 공통 검증은 핵심 요약에 한 번 |
| 내부 말과 규칙 나열 | 플러그인 기본 내부 용어(게이트, 작업 메모, 리더, 작성자, 에이전트 폴더, 하네스, 프리플라이트), 메모 필드 이름 나열(`notes-leak`), 한 문장 넷 이상 나열(`list-chain`)을 막는다 |
| `~함`, `~음` 종결 | 모든 줄을 `~다`로 끝낸다(`noun-ending`). 다음 할 일만 예외 |
| 막연한 제목 `… 개선` | 동사로 끝나는 성과(`title-vague`) |
| 항목 제목이 진행 현황 이름과 다름 | 항목 제목 왼쪽은 프로필 기능 이름이나 작업 항목 이름(`item-feature`) |
| 입력에 없는 시험 수 | `숫자+개·건·회·번·배·초·분·시간`은 작업 메모에 있는 것만(`unsourced-number`) |
| 줄 220자, 기록 40줄 | 줄 160자(세부 줄 120자), 기록 70줄. 자세함은 줄 수로 낸다 |
| 프로젝트 소개 없음 | 프로필 `소개:` 한 줄이 Notion 작업로그 첫 줄과 포트폴리오에 들어간다 |
| 진행 현황: 기능 · 진행 · 최근 변화 · 남은 일 | 완료 칸과 `## 완료 기록` 추가. index.md에도 완료 기록 |

## 1.3.0에서 바뀐 것

- 여러 저장소를 하나의 프로젝트로 기록한다. git 저장소가 아닌 폴더 바로 아래에 저장소가 있으면(최대 20개) 그 폴더에서 실행해, 모든 저장소의 내 커밋을 한 기록으로 묶는다. 20개를 넘으면 `preflight`가 실패한다.
- 기록은 그 폴더의 `<에이전트 폴더>/log-part/`에 하나로 쌓인다. 저장할 때마다 묶인 저장소 목록을 `workspace.md`와 state.json에 다시 적고, 저장소가 늘거나 줄어도 하나라도 겹치면 같은 프로젝트로 본다. 다른 묶음에서 복사한 기록은 거부한다.
- 프로필 경로는 `저장소 폴더/경로`로 적는다. 저장소 폴더 이름만 쓰면 그 저장소 전체다. 워크스페이스의 작업 단위는 기간 방식만 쓴다.
- `preflight`는 저장소마다 원격과 커밋 신원을 따로 검사하고, 결과에 `members`(묶인 저장소 폴더)를 담는다. `.run.json`의 `sources`가 커밋별 저장소를 알려 준다.

## 1.2.0에서 바뀐 것

실제 Notion 기록을 객관 평가해 나온 문제(바깥 독자에게 불친절함, 항목이 기능·커밋별로 쪼개짐, 검증 없는 단정, 재실행마다 달라지는 문장, 의미 없는 진행률과 `-` 칸, 따로 떨어진 포트폴리오 문장)를 고쳤다.

| 전 | 지금 |
|---|---|
| 항목 필드 `문제 · 한 일 · 결과` (무엇을 구현했나만 묻는다) | `배경`(이전 상태와 그로 인한 문제·영향) · `접근`(진단과 판단, 대안 대비 이유) · `결과`(바뀐 점과 검증 근거) |
| 필수 절에 `포트폴리오 문장` | 그 절은 없다(게이트가 막는다). 필수는 `핵심 요약`, `한 일`. 선택은 `기술 판단`, `문제 해결`, `오늘 변화`, `다음 할 일` |
| 작업 메모: 이전 상태 · 사실 · 판단(선택) · 확인(선택) | 항목마다 `이전 상태` 1 · `영향` 1 · `사실` 2+ · `판단` 1+(`<선택> — <이유>`) · `검증` 1(구체적 근거 또는 `없음`). 항목은 3개 이하 |
| 검증 없이도 결과를 단정 | 검증이 `없음`이면 그 항목 결과에 `확인`·`검증`·`통과`를 쓸 수 없다(`unverified-claim`) |
| 같은 날짜를 다시 실행하면 메모를 새로 써 문장이 달라짐 | 통과한 메모를 `log-part/notes/<날짜>.md`에 저장(`notes --check --save --entry -`). 근거 지문이 같으면 저장본을 그대로 쓰고, `다시 정리`일 때만 새로 쓴다 |
| 한 일 항목 3~5개, 기능·커밋별로 쪼개짐 | 목표·성과 단위로 최대 3개(`too-many-items`). 나머지는 `- 그 밖에 —` |
| 프로젝트 안의 말 그대로 | 프로필 `내부 용어:`를 기록에서 막고, 내부 매개변수 값(글자 수·줄 수 상한)은 문장에 쓰지 않는다. 바깥 사람이 읽는 글이 기준 |
| 진행 상황 표(퍼센트·`-` 칸) | 표 없음. 선택 절 `오늘 변화`는 손댄 기능마다 `- <기능> — <변화>`(마일스톤이 있으면 `(마일스톤 n/m)`). Notion 진행 현황은 마일스톤이 있는 기능만 %, 나머지는 `마일스톤 미설정`. 경로가 사라진 기능은 진행 출력에서 빠지고, 빈 `-` 값은 게이트가 막음 |
| `preflight`의 `notion-mcp`가 항상 ok | 상태 `unknown`(리더가 자기 도구 목록에서 확인해야 함). preflight를 실패시키지 않는다 |
| 이전 상태 판정이 "기존·이전·…" 같은 말에만 의존 | `~했고`, `~였고`, `~었습니다`, `~했습니다` 같은 과거 서술도 `만`·`뿐`·`그대로`·`채`·`이후` 같은 조건·한계 말과 함께면 통과. 목표 문장은 계속 막음 |
| 기본 Notion 위치 `개인 페이지 / <프로젝트> / 작업로그` | `개인페이지 / project / <프로젝트> / 작업로그` |

## 1.1.3에서 바뀐 것

- 작업 메모가 검사되는 산출물이 됐다. `notes --check --entry -`가 항목마다 이전 상태 1개, 사실 2개 이상(15자 이상, 중복 없음), 목표만 쓴 이전 상태 금지, 유출 금지를 확인하고 종료 코드 2로 부족한 점을 알려 준다. 리더는 통과한 뒤에만 작성자를 부른다.
- 게이트에 `problem-goal-only`가 추가됐다. 문제 줄(1.2.0부터 배경 줄)에 이전 상태 말이 없거나 목표 문장으로 끝나면 막는다.
- 리더는 커밋마다 `git show --stat`과 코드 변경, 모듈 문서·시험을 읽어야 하고, 작성자는 메모와 JSON의 사실만 쓴다.

## 1.1.2에서 바뀐 것

- `gate`, `korean`, `write`, `write-portfolio`가 `--entry -`로 표준 입력의 초안을 받는다. 임시 파일이 남지 않는다(`korean`은 프로세스 안에서만 만들고 지운다). 파일 경로도 그대로 된다.
- `notion-set`이 state.json뿐 아니라 `log-part/notion.md`의 위치 표도 다시 쓴다. 파일이 없으면 기본 서식으로 만들고, 표 밖의 글은 건드리지 않는다.
- `preflight`에 `log-part-writable` 검사가 추가됐다. 쓰기가 막히면 호스트별 조치를 알려 준다(사전 조건 참고).

## 사전 조건

- git, 원격이 있는 저장소, git 사용자 신원, git에서 무시되는 에이전트 폴더, Python 3.12 이상. 여러 저장소를 묶을 때는 저장소마다 원격과 신원이 있어야 하고, 묶음 루트의 에이전트 폴더는 저장소 밖이라 무시 검사를 통과한다.
- `<에이전트 폴더>/log-part/` 쓰기 권한. 호스트가 설정 폴더를 보호하면 `preflight`의 `log-part-writable`이 실패하고 조치를 알려 준다. 호스트 설정은 자동으로 고치지 않는다.
  - Claude Code: `Edit(.claude/log-part/**)` 허용 또는 쓰기 확인창 승인.
  - Codex: 이 세션에만 `codex -c 'sandbox_workspace_write.writable_roots=["<프로젝트>/.codex"]'`로 실행하거나, 대화형이면 권한 상승 요청 승인.
  - Cursor, Grok: 쓰기 확인창 승인.

## 1.1.1에서 바뀐 것

- 기록 길이: 비어 있지 않은 줄 40줄 초과, 필드 한 줄 220자 초과를 게이트가 막는다. `그 밖에`는 최대 3개다.
- 진행 상황 표에는 그날 손댄 기능만 쓴다(`prepare`가 `touched_features`를 낸다). `손대지 않음` 행은 막힌다.
- 다음 할 일에서 같은 동작의 반복은 한 줄로 합친다. 기술 판단은 `- **선택** — 이유` 꼴만 허용한다.
- 새 명령 `forget --date <날짜>`: 그 날짜 기록 파일, state.json, index.md 항목을 지우고 Notion 페이지 id·url을 알려 준다. Notion MCP는 페이지를 휴지통으로 보낼 수 없어 사용자가 직접 삭제한다.

## 명령과 날짜

| 입력 | 하는 일 |
|---|---|
| `/clonamic-task-log` , `오늘` | 오늘 한 작업을 기록 |
| 날짜 뒤 `다시 정리` | 저장된 작업 메모를 쓰지 않고 새로 정리 |
| `어제`, `그제` | 하루 전, 이틀 전 |
| `2026-10-01`, `10-01` | 그 날짜(`MM-DD`는 올해) |
| `09-28~10-02` | 기간. 파일은 `2026-09-28~2026-10-02.md`, Notion 제목은 `0928~1002` |
| `설정` | 파트, 담당 기능, 신원, Notion 위치 고치기 |
| `포트폴리오 정리` | 기록 전체를 포트폴리오 요약 페이지로 묶기 |
| `노션 동기화` | 로컬에만 쓰인 기록을 Notion에 올리기 |

그 날짜에 작성한 내 커밋을 모은다. 같은 날짜를 다시 실행하면 같은 기록과 같은 페이지를 갱신하고, 근거와 본문이 같으면 아무것도 바꾸지 않는다.

## 전체 흐름

1. 사전 조건 확인(`preflight`). 첫 실행이면 한 번 묻고 프로필과 Notion 위치를 만든다.
2. clonamic-korean 확인(`korean`). 없으면 호스트에 맞게 사용자 수준에 설치한다(홈 폴더 아래, 프로젝트 안에는 설치하지 않음). 실패하면 한 줄로 알리고 내장 문체 규칙으로 계속한다. 공식 저장소는 https://github.com/clonamic/plugin 이다.
3. 수집(`prepare --on`). 날짜를 해석하고 내 커밋을 모아, 이유가 분명한 것만 거르고, 경로와 식별자를 지운 JSON을 만든다.
4. 리더가 실제 변경을 읽고 작업 메모를 쓴다. 문제 하나씩 3개 이하 항목에 이전 상태·영향·사실(2~4)·판단·검증과, 있으면 전후·완료를 기능 말로만 쓰고, 통과하면 날짜별로 저장한다. 같은 날짜를 다시 실행하고 근거가 같으면 저장본을 쓴다.
5. 작성자 서브에이전트 `clonamic-task-logger`가 JSON, 저장된 작업 메모, 서식으로 기록을 쓴다. 파일이나 diff는 보지 못한다.
6. 리더가 검토하고 `gate`로 유출, 통계 문장, 얼버무림, 라벨, 형식을 검사한다.
7. `korean --entry`로 한국어 검사. 막히면 작성자에게 돌려 다시 쓴다.
8. `write`로 저장하고, Notion에 날짜 페이지와 진행 현황 페이지를 만든다.

작성자 모델은 Claude Code가 플러그인 에이전트(Sonnet), Codex가 가장 최신 `*-luna`(현재 `gpt-6-luna`)의 일반 서브에이전트, Cursor와 Grok이 플러그인 에이전트 또는 Sonnet 급 일반 서브에이전트다. 서브에이전트를 쓸 수 없으면 리더가 같은 본문을 따라 직접 쓴다.

## 기록 형식

```text
# 2026-09-29 · 영수증 금액을 사진 한 장으로 인식
## 핵심 요약
## 한 일            (항목 하나에 문제 하나, 최대 3개. 배경 · 접근(+세부 줄 2~4) · 전후(선택) · 결과)
## 완료 정리        (끝난 마일스톤·기능·작업이 있을 때만. 만든 것 · 거쳐 온 길 · 남은 한계)
## 다음 할 일       (선택)
```

- 항목마다 세부 줄로 바꾼 것을 하나씩 자세히 쓰고, 나머지 작은 일은 `그 밖에` 한 줄(최대 3개)로 묶는다. 한 사실은 한 번만 쓴다. 70줄을 넘으면 게이트가 막는다.
- 측정한 값에만 `(측정)`을 붙인다. 다른 라벨, 지문, 해시, HTML 주석은 기록과 Notion 어디에도 없다.
- 예시와 절별 쓰는 법은 `skills/clonamic-task-log/references/entry.md`에 있다.

## Notion 구조

```text
개인페이지 / project / <프로젝트명> / 작업로그
├── 진행 현황        기능 · 진행(마일스톤이 있는 기능만 %) · 완료 · 최근 변화 · 남은 일, 완료 기록
├── 포트폴리오 요약   역할 한 줄 · 대표 성과 · 기능별 기여 · 사용 기술 · 문제 해결 사례
├── 2026-10-05       첫 블록이 대표 성과, 본문은 로컬 기록과 같음
└── 0928~1002        기간 기록
```

같은 제목 후보가 0개면 만들고, 1개면 갱신하고, 2개 이상이면 멈추고 묻는다. 생성 응답이 끊겨도 다시 만들지 않고 검색·조회로 찾는다.

## 저장과 프로젝트 분리

- 저장하는 것은 모두 `<프로젝트>/<에이전트 폴더>/log-part/` 안에 있고 CLI(`save`, `write`, `notion-set`, `forget`)만 쓴다. 에이전트 폴더는 Claude Code `.claude`, Codex `.codex`, Cursor `.cursor`, Grok `.grok`다.
- 검사를 통과한 작업 메모는 `log-part/notes/<날짜>.md`에 날짜별로 저장된다(근거 지문은 state.json에만 있다). `forget`은 그 날짜의 메모도 지운다.
- state.json이 프로젝트 신원(원격 주소 해시, 루트 경로)을 기억한다. 다른 프로젝트에서 복사한 log-part는 거부하고, 같은 프로젝트를 옮겼으면 `rebind`로 다시 연결한다.
- `.env`, 자격 증명, `.git` 내부, 의존성, 캐시는 읽지 않는다. git은 읽기 명령만 쓴다.
