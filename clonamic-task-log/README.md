# clonamic-task-log

## 핵심 요약

- 지금 열린 프로젝트에서 내가 직접 한 git 작업을 날짜별 작업 기록으로 정리하는 플러그인이다.
- 기록은 나만 보는 비공개 자료이고 목적은 포트폴리오다. 모든 기록을 그대로 포트폴리오에 옮길 수 있는 1인칭 실무 한국어로 쓴다.
- 명령은 `/clonamic-task-log` 하나이고, 명시적으로 입력했을 때만 실행된다.
- 결과는 `<프로젝트>/<에이전트 폴더>/log-part/`의 로컬 파일과 Notion `개인 페이지 / <프로젝트명> / 작업로그` 아래 페이지다.
- 파일 이름, 경로, 커밋 해시, 비밀 정보는 기록과 Notion 어디에도 남지 않는다. 게이트가 통과시키지 않으면 저장도 동기화도 하지 않는다.

## 명령과 인자

| 입력 | 하는 일 |
|---|---|
| `/clonamic-task-log` | 지난 실행 이후 내 커밋을 기록(첫 실행이면 최근 7일) |
| `/clonamic-task-log 오늘` | 오늘 0시부터 |
| `/clonamic-task-log 이번 주` | 이번 주 월요일부터 |
| `/clonamic-task-log 9월 28일부터` | 그 날짜부터 |
| `/clonamic-task-log 설정` | 파트, 담당 기능, 신원, 작업 단위, Notion 위치 고치기 |
| `/clonamic-task-log 포트폴리오 정리` | 기록 전체를 포트폴리오 요약 페이지로 묶기 |
| `/clonamic-task-log 노션 동기화` | 로컬에만 쓰인 기록을 Notion에 올리기 |
| `/clonamic-task-log 2026-10-01 다시 정리` | 지난 날짜 기록을 새 근거로 다시 쓰기(이때만 과거 기록을 바꾼다) |

## 사전 조건

| 조건 | 확인 방법 | 안 될 때 |
|---|---|---|
| git 설치 | `preflight` | 설치 안내 |
| 원격이 있는 git 저장소 안 | `preflight` | 저장소 안에서 실행, `git remote add` 안내 |
| git 사용자 신원 | `preflight` | `git config user.name/user.email` 안내 |
| 에이전트 폴더가 git에서 무시됨 | `git check-ignore` | `.gitignore` 또는 `.git/info/exclude`에 한 줄 추가 안내. 자동으로 고치지 않는다 |
| Python 3.12 이상 | 스크립트 첫 줄 | `uv python install 3.12` 안내 |
| Notion MCP 도구 | 에이전트가 자기 도구 목록을 확인 | 멈추지 않고 로컬만 기록, Notion은 `승인 시 진행`으로 보고 |

## 저장 구조 (프로젝트마다 따로)

```text
<프로젝트>/<에이전트 폴더>/log-part/     .claude · .codex · .cursor · .grok
├── profile.md            파트, 담당 기능·경로·마일스톤, 신원, 작업 단위, 시간대, 상한
├── notion.md             Notion 위치(경로, 페이지 ID·URL)와 하위 페이지 구조
├── notion-template.md    Notion 페이지 템플릿 사본(사용자가 고치면 그대로 따름)
├── 2026-10-05.md         날짜 기록(같은 날 다시 실행하면 한 기록으로 합침)
├── index.md              타임라인, 기능별 진행 정도, 작업 단위
├── portfolio.md          포트폴리오 요약(요청했을 때)
└── state.json            프로젝트 신원, 브랜치별 커서, 처리한 커밋, 증거 지문, Notion ID
```

## Notion 구조

```text
개인 페이지
└── <프로젝트명>
    └── 작업로그
        ├── 진행 현황        기능별 진행률(추정), 실행마다 갱신
        ├── 포트폴리오 요약   포트폴리오 정리 때 생성·갱신
        └── 2026-10-05       날짜 기록(제목은 날짜만)
```

- 경로가 없거나 첫 실행이면 위 구조를 먼저 만들고, 페이지 ID를 notion.md와 state.json에 적는다.
- 같은 제목 후보가 0개면 만들고, 1개면 갱신하고, 2개 이상이면 멈추고 묻는다.
- 증거 지문과 본문이 같으면 쓰지 않는다. 생성 응답이 끊겨도 다시 만들지 않고 검색·조회로 찾는다. 쓴 뒤 다시 조회해 제목·절·지문을 확인한다.

## 처리 단계와 담당

| 단계 | 담당 | 내용 |
|---|---|---|
| 준비 | 스크립트 `preflight` + 리더 | 사전 조건 확인, 첫 실행 기본값 감지(신원, 담당 폴더 후보, 스프린트·릴리스 주기) |
| 첫 실행 설정 | 리더 | 한 메시지로 묻고 profile.md·notion.md 작성, Notion 페이지 생성 |
| 수집 → 거르기 → 점수 → 진행률 → 익명화 | 스크립트 `prepare` | 아래 규칙대로 처리해 익명화 JSON 출력 |
| 본문 작성 | 작성자 서브에이전트 `clonamic-task-logger` | 익명화 JSON과 작성법만 보고 한국어 기록 작성. 파일을 읽거나 쓰지 않음 |
| 검토·게이트 | 리더 + 스크립트 `gate` | 작성법 대조, 유출·형식·라벨 검사. 막히면 작성자에게 돌려 수정 |
| 저장 | 스크립트 `write` | 날짜 파일 블록 교체, state.json·index.md 갱신, 같은 근거면 건너뜀 |
| Notion 동기화 | 리더(Notion MCP) | 날짜 페이지 만들기·갱신, 진행 현황 갱신, 확인 |

작성자 모델: Claude Code는 플러그인 에이전트(Sonnet), Codex는 같은 본문을 지시문으로 준 일반 서브에이전트(`luna`), Cursor·Grok는 플러그인 에이전트나 일반 서브에이전트(Sonnet 급). 서브에이전트가 없으면 리더가 직접 쓰고 보고서에 한 줄로 알린다.

## 거르기와 중요도

- **빼는 것(이유별 건수를 보고):** 병합 커밋, 다른 브랜치의 같은 변경(patch-id), 봇 커밋, 서로 상쇄되는 되돌림 쌍, 제외 경로·범위 밖만 바꾼 커밋, 빈 커밋, 생성·잠금·외부 파일만 바꾼 커밋, 공백만·주석만 바꾼 커밋.
- **나머지는 모두 넣는다.** 7건 이하면 모두 자세히, 넘으면 상위 5건(60점 이상은 7건까지) 자세히, 나머지는 `기타 n건(유형별)`.
- **중요도(0–100):**

| 요소 | 점수 |
|---|---|
| 유형 | 기능·성능 40, 수정 30, 구조 개선 22, 변경 20, 테스트 18, 문서 10, 되돌림 8, 유지보수 6, 스타일 4 |
| 규모 | 25 × log10(1+줄 수) / log10(1001), 최대 25(생성·잠금 파일 제외) |
| 새로 만든 것 | 새 모듈(한 폴더에 새 파일 2개 이상) 10, 새 코드 파일 6 |
| 담당 기능·핵심 경로 | 담당 기능 8, 그 밖의 핵심 폴더 5 |
| 테스트 추가 | 제품 코드와 함께 테스트 추가 7 |
| 측정값 | 커밋 메시지에 단위가 있는 전후 값 10 |

- 유형은 커밋 규약 접두어, 첫 동사, 키워드, 바뀐 파일 종류 순으로 정한다.
- 시간대(기본 Asia/Seoul)로 날짜 경계를 정한다. 한 폴더에서 생성 파일이 25개를 넘으면 한 묶음으로 센다. 최대 커밋 200·최대 파일 2000을 넘으면 최신부터 담고 "일부만 수집"으로 표시한다.

## 진행 정도 추정

- 마일스톤이 있으면 70×끝낸 비율 + 10×활동 + 10×테스트 + 10×미완 표시 적음. 모두 끝나기 전 95% 이하, 모두 끝나면 90% 이상.
- 마일스톤이 없으면 35×코드 있음 + 25×활동 + 15×테스트 + 10×미완 표시 적음. 최대 85%.
- 활동 = min(1, 내 커밋 수 ÷ 10), 미완 표시 = TODO·FIXME·미구현 표시 수. 5% 단위, 항상 "추정"과 근거 한 구절을 함께 쓴다.
- 작업 단위(스프린트 등)가 있으면 단위 기간, 기간 경과, 그 기간에 다룬 기능의 평균으로 묶는다.

## 익명화와 게이트

| 대상 | 처리 |
|---|---|
| 경로·파일 이름 | 담당 기능 라벨, 없으면 일반적인 한국어 영역 이름(인증, 테스트, 문서 …) |
| 커밋 메시지 | 코드 조각, URL, 메일, 비밀 값, IP, 호스트, 경로, 파일 이름, 환경 변수, 티켓·이슈 번호, 해시, 코드 식별자, 저장소 내부 이름, 비공개 용어를 `‹비공개›`로 지움 |
| 최종 기록 | 위 항목이 하나라도 남거나, 형식(절 순서, 필수 필드, 증거 지문)이 틀리거나, 라벨 없는 수치·목록에 없는 라벨·자리표시자가 있으면 저장과 동기화를 막음 |

- 한국어 조사가 바로 붙은 식별자(`config.py를`)도 잡는다. `CI/CD`, `UTF-8`, `Node.js`, `3/5` 같은 일반 표기는 통과한다.
- 커밋 해시와 경로는 state.json과 증거 지문 안에만 있다.

## 기록 형식과 증거 라벨

- 절 순서: 한눈에 보기 → 목표·맥락 → 포트폴리오 하이라이트 → 작업 상세 → 기술적 의사결정 → 문제 해결 기록 → 검증·측정 결과 → 진행 정도 → 기여·영향 → 회고·다음 작업 → 근거·신뢰도. 근거 없는 절은 뺀다.
- 라벨: `[측정]` git에서 센 값·커밋의 측정값, `[판단]` 해석·추정, `[전달]` 사용자가 알려 준 사실, `[가정]` 확인 못 한 전제, `[미확인]` 실행 못 한 검증.
- 근거 수준: A git 저자 일치 커밋, B 파일·결과 시각, C 사용자 제공.

## 프로젝트 분리

- 모든 명령이 현재 폴더의 `git rev-parse --show-toplevel`로 프로젝트를 정하고 그 프로젝트의 log-part만 쓴다. 홈 폴더에는 아무것도 저장하지 않는다.
- state.json에 원격 주소 해시와 루트 경로를 적는다. 다른 프로젝트에서 복사해 온 log-part는 거부한다. 같은 프로젝트를 옮겼으면 `rebind`로 확인한다.
- Notion 기본 경로와 notion.md도 프로젝트마다 따로다.

## 읽기 경계

- `.env`, 자격 증명·키 파일, `.git` 내부, 의존성, 캐시, 모델·체크포인트 폴더는 읽지 않는다.
- git은 읽기 명령만 쓴다. 프로젝트 파일, `.gitignore`, git 설정을 고치지 않는다.
