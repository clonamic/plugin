# clonamic-task-log

## 핵심 요약

- 지금 열린 프로젝트에서 내가 그날 직접 한 git 작업을, 포트폴리오에 바로 옮길 수 있는 작업 기록으로 정리하는 플러그인이다.
- 명령은 `/clonamic-task-log [날짜]` 하나이고, 명시적으로 입력했을 때만 실행된다. 날짜를 생략하면 오늘이다.
- 기록은 커밋 통계가 아니라 그날 무엇을 왜 어떻게 해서 무엇이 달라졌는지를 쓴다. 에이전트가 실제 변경을 읽고 쓴 작업 메모를 바탕으로 작성자 서브에이전트가 한국어로 쓴다.
- 결과는 `<프로젝트>/<에이전트 폴더>/log-part/`의 로컬 파일과 Notion `개인 페이지 / <프로젝트명> / 작업로그` 아래 페이지다.
- 파일 이름, 경로, 커밋 해시, 비밀 정보와 통계 문장, 얼버무림은 게이트가 막는다. 게이트를 통과하지 않으면 저장도 동기화도 하지 않는다.

## 1.1.2에서 바뀐 것

- `gate`, `korean`, `write`, `write-portfolio`가 `--entry -`로 표준 입력의 초안을 받는다. 임시 파일이 남지 않는다(`korean`은 프로세스 안에서만 만들고 지운다). 파일 경로도 그대로 된다.
- `notion-set`이 state.json뿐 아니라 `log-part/notion.md`의 위치 표도 다시 쓴다. 파일이 없으면 기본 서식으로 만들고, 표 밖의 글은 건드리지 않는다.
- `preflight`에 `log-part-writable` 검사가 추가됐다. 쓰기가 막히면 호스트별 조치를 알려 준다(사전 조건 참고).

## 사전 조건

- git, 원격이 있는 저장소, git 사용자 신원, git에서 무시되는 에이전트 폴더, Python 3.12 이상.
- `<에이전트 폴더>/log-part/` 쓰기 권한. 호스트가 설정 폴더를 보호하면 `preflight`의 `log-part-writable`이 실패하고 조치를 알려 준다. 호스트 설정은 자동으로 고치지 않는다.
  - Claude Code: `Edit(.claude/log-part/**)` 허용 또는 쓰기 확인창 승인.
  - Codex: 이 세션에만 `codex -c 'sandbox_workspace_write.writable_roots=["<프로젝트>/.codex"]'`로 실행하거나, 대화형이면 권한 상승 요청 승인.
  - Cursor, Grok: 쓰기 확인창 승인.

## 1.1.1에서 바뀐 것

- 기록 길이: 비어 있지 않은 줄 40줄 초과, 필드 한 줄 220자 초과를 게이트가 막는다. `그 밖에`는 최대 3개다.
- 진행 상황 표에는 그날 손댄 기능만 쓴다(`prepare`가 `touched_features`를 낸다). `손대지 않음` 행은 막힌다.
- 다음 할 일에서 같은 동작의 반복은 한 줄로 합친다. 기술 판단은 `- **선택** — 이유` 꼴만 허용한다.
- 새 명령 `forget --date <날짜>`: 그 날짜 기록 파일, state.json, index.md 항목을 지우고 Notion 페이지 id·url을 알려 준다. Notion MCP는 페이지를 휴지통으로 보낼 수 없어 사용자가 직접 삭제한다.

## 1.1.0에서 바뀐 것

| 전 | 지금 |
|---|---|
| 지난 실행 이후의 커밋을 실행한 날짜에 기록 | `/clonamic-task-log [날짜]`로 일한 날짜를 골라 그 날짜 파일과 페이지에 기록 |
| "기능 커밋 1건, 파일 32개 변경" 같은 통계 | 문제 · 한 일 · 결과로 쓴 실제 내용 |
| 11개 절, `[측정]` `[판단]` 같은 라벨, 지문 줄 | 핵심 요약 · 한 일 · 기술 판단 · 문제 해결 · 진행 상황 · 다음 할 일 · 포트폴리오 문장. 라벨과 메타데이터 없음 |
| "~으로 보입니다" 같은 추측 | 근거 있는 사실만 행위자 문장으로. 얼버무림은 게이트가 막음 |
| 수치 라벨 | 측정한 값 뒤에 `(측정)`만. 입력에 없는 숫자는 막음 |
| 스크립트 요약만 보고 작성 | 리더가 실제 변경을 읽고 작업 메모를 써서 작성자에게 전달 |
| 한국어 검사 없음 | clonamic-korean으로 초안 검사. 없으면 호스트별로 사용자 수준에 자동 설치 |
| Notion 제목 `2026-10-05`, 본문에 지문 | 제목 `YYYY-MM-DD`(기간 `MMDD~MMDD`), 첫 블록이 대표 성과, 메타데이터 없음 |

## 명령과 날짜

| 입력 | 하는 일 |
|---|---|
| `/clonamic-task-log` , `오늘` | 오늘 한 작업을 기록 |
| `어제`, `그제` | 하루 전, 이틀 전 |
| `2026-10-01`, `10-01` | 그 날짜(`MM-DD`는 올해) |
| `09-28~10-02` | 기간. 파일은 `2026-09-28~2026-10-02.md`, Notion 제목은 `0928~1002` |
| `설정` | 파트, 담당 기능, 신원, Notion 위치 고치기 |
| `포트폴리오 정리` | 기록 전체를 포트폴리오 요약 페이지로 묶기 |
| `노션 동기화` | 로컬에만 쓰인 기록을 Notion에 올리기 |

그 날짜에 작성한 내 커밋을 모은다. 같은 날짜를 다시 실행하면 같은 기록과 같은 페이지를 갱신하고, 근거와 본문이 같으면 아무것도 바꾸지 않는다.

## 전체 흐름

1. 사전 조건 확인(`preflight`). 첫 실행이면 한 번 묻고 프로필과 Notion 위치를 만든다.
2. clonamic-korean 확인(`korean`). 없으면 호스트에 맞게 사용자 수준에 설치한다(홈 폴더 아래, 프로젝트 안에는 설치하지 않음). 실패하면 한 줄로 알리고 내장 문체 규칙으로 계속한다. 공식 저장소는 https://github.com/clonamic/plugin 이다.
3. 수집(`prepare --on`). 날짜를 해석하고 내 커밋을 모아, 이유가 분명한 것만 거르고, 경로와 식별자를 지운 JSON을 만든다.
4. 리더가 실제 변경을 읽고 작업 메모를 쓴다. 문제, 한 일, 결과, 판단을 기능 말로만 쓴다.
5. 작성자 서브에이전트 `clonamic-task-logger`가 JSON, 작업 메모, 서식으로 기록을 쓴다. 파일이나 diff는 보지 못한다.
6. 리더가 검토하고 `gate`로 유출, 통계 문장, 얼버무림, 라벨, 형식을 검사한다.
7. `korean --entry`로 한국어 검사. 막히면 작성자에게 돌려 다시 쓴다.
8. `write`로 저장하고, Notion에 날짜 페이지와 진행 현황 페이지를 만든다.

작성자 모델은 Claude Code가 플러그인 에이전트(Sonnet), Codex가 가장 최신 `*-luna`(현재 `gpt-6-luna`)의 일반 서브에이전트, Cursor와 Grok이 플러그인 에이전트 또는 Sonnet 급 일반 서브에이전트다. 서브에이전트를 쓸 수 없으면 리더가 같은 본문을 따라 직접 쓴다.

## 기록 형식

```text
# 2026-09-29 · 영수증 OCR 파이프라인 개선
## 핵심 요약
## 한 일            (기능마다 문제 · 한 일 · 결과)
## 기술 판단        (선택)
## 문제 해결        (선택)
## 진행 상황
## 다음 할 일       (선택)
## 포트폴리오 문장
```

- 중요한 작업 3~5개를 자세히 쓰고 나머지는 `그 밖에` 한 줄(최대 3개)로 묶는다. 보통 15~35줄이고 40줄을 넘으면 게이트가 막는다.
- 측정한 값에만 `(측정)`을 붙인다. 다른 라벨, 지문, 해시, HTML 주석은 기록과 Notion 어디에도 없다.
- 예시와 절별 쓰는 법은 `skills/clonamic-task-log/references/entry.md`에 있다.

## Notion 구조

```text
개인 페이지 / <프로젝트명> / 작업로그
├── 진행 현황        기능 · 진행률 · 최근 변화 · 남은 일
├── 포트폴리오 요약   역할 한 줄 · 대표 성과 · 기능별 기여 · 사용 기술 · 문제 해결 사례
├── 2026-10-05       첫 블록이 대표 성과, 본문은 로컬 기록과 같음
└── 0928~1002        기간 기록
```

같은 제목 후보가 0개면 만들고, 1개면 갱신하고, 2개 이상이면 멈추고 묻는다. 생성 응답이 끊겨도 다시 만들지 않고 검색·조회로 찾는다.

## 저장과 프로젝트 분리

- 저장하는 것은 모두 `<프로젝트>/<에이전트 폴더>/log-part/` 안에 있고 CLI(`save`, `write`, `notion-set`, `forget`)만 쓴다. 에이전트 폴더는 Claude Code `.claude`, Codex `.codex`, Cursor `.cursor`, Grok `.grok`다.
- state.json이 프로젝트 신원(원격 주소 해시, 루트 경로)을 기억한다. 다른 프로젝트에서 복사한 log-part는 거부하고, 같은 프로젝트를 옮겼으면 `rebind`로 다시 연결한다.
- `.env`, 자격 증명, `.git` 내부, 의존성, 캐시는 읽지 않는다. git은 읽기 명령만 쓴다.
