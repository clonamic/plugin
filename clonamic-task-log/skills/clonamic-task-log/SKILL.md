# 작업 기록

이 스킬은 사용자가 `/clonamic-task-log`를 직접 입력했을 때만 실행한다. 커밋, 작업 보고, 다른 스킬 실행 중에 스스로 켜지 않는다.

지금 열린 프로젝트에서 사용자가 직접 한 git 작업을 날짜별 작업 기록으로 정리한다. 기록은 사용자 혼자 보는 비공개 자료이고 목적은 포트폴리오다. 모든 기록을 포트폴리오에 바로 옮길 수 있는 성과 중심의 1인칭 실무 한국어로 쓴다. 파일 이름, 경로, 비밀 정보는 어디에도 남기지 않는다.

## 0. 공통 규칙

- **스크립트.** 이 `SKILL.md`가 있는 폴더를 `SKILL_DIR`로 두고 `python3 "$SKILL_DIR/scripts/tasklog.py" --agent-dir <에이전트 폴더> <명령>`으로 실행한다. 모든 명령은 JSON 하나를 출력한다. Python 3.12 이상, 표준 라이브러리만 쓴다. `python3 --version`이 3.12보다 낮으면 `uv python install 3.12`(또는 OS 패키지 관리자)로 설치해 그 인터프리터로 실행한다. 낮은 버전으로 우회하지 않는다.
- **에이전트 폴더.** 지금 실행 중인 호스트의 폴더를 쓴다. Claude Code `.claude`, Codex `.codex`, Cursor `.cursor`, Grok `.grok`.
- **프로젝트 분리.** 모든 명령은 현재 작업 폴더에서 `git rev-parse --show-toplevel`로 프로젝트를 정하고 `<프로젝트>/<에이전트 폴더>/log-part/`만 읽고 쓴다. 홈 폴더나 다른 프로젝트에 아무것도 저장하지 않는다. state.json에 프로젝트 신원(원격 주소 해시, 루트 경로)을 적어 두고, 다른 프로젝트에서 복사해 온 log-part는 거부한다. 같은 프로젝트를 옮긴 것이면 사용자 확인 뒤 `rebind`를 실행한다.
- **읽기 경계.** `.env`, 자격 증명·비밀 키 파일, `.git` 내부, 의존성(`node_modules`, `vendor`, `.venv`), 캐시, 모델·체크포인트 폴더는 읽지 않는다. git은 읽기 명령만 쓴다. 프로젝트 파일, `.gitignore`, git 설정을 고치지 않는다.
- **비공개 정보.** 기록, 보고서, Notion 어디에도 파일 이름, 경로, 함수·변수 이름, 커밋 해시, 브랜치·티켓 번호, URL, 메일, 호스트, IP, 환경 변수, 키를 쓰지 않는다. 기능 라벨로 쓴다. 커밋 해시와 경로는 state.json과 증거 지문 안에만 있다.

## 1. 인자 읽기

| 인자 | 할 일 | prepare 옵션 |
|---|---|---|
| (없음) | 지난 실행 이후 내 커밋. 첫 실행이면 첫 기록 범위(기본 7일) | 없음 |
| `오늘` | 오늘 0시(프로필 시간대)부터 | `--since <오늘> --until <오늘>` |
| `이번 주` | 이번 주 월요일부터 | `--since <월요일>` |
| `<날짜>부터`, `9월 28일부터` | 그 날짜부터 | `--since <날짜>` |
| `<날짜>`, `<날짜>~<날짜>` | 그 날, 그 기간 | `--since … --until …` |
| `설정` | 프로필·Notion 위치 고치기 | [setup](references/setup.md) 4절 |
| `포트폴리오 정리` | 기록 전체를 포트폴리오 요약으로 묶기 | 6절 |
| `노션 동기화` | 로컬에만 쓰인 최근 기록을 Notion에 올리기 | 5절만 |
| `<날짜> 다시 정리` | 지난 날짜 기록을 새 근거로 다시 쓰기(명시적 요청일 때만) | `--date <날짜> --since <날짜> --until <날짜>`, write에 `--replace-past` |

날짜는 프로필의 시간대(기본 Asia/Seoul) 기준이다. 해석이 모호하면 가장 좁은 범위로 정하고 보고서에 적는다.

## 2. 준비

1. `preflight`를 실행한다. `ok`가 false면 실패한 항목의 `fix`를 그대로 사용자에게 보여 주고 멈춘다. `.gitignore`나 `.git/info/exclude`를 대신 고치지 않는다.
2. Notion MCP 도구(검색, 조회, 페이지 생성, 페이지 수정)가 내 도구 목록에 있는지 직접 확인한다. 스크립트는 이것을 알 수 없다. 없으면 멈추지 않는다. 로컬 기록까지 하고 Notion은 보고서에 `승인 시 진행`으로 남긴다.
3. `first_run`이 true면 [setup](references/setup.md)대로 한 메시지로 묻고, 답을 받아 profile.md·notion.md·notion-template.md를 만들고 Notion 페이지를 만든다. 답을 기다리는 동안 다음 단계로 가지 않는다.

## 3. 수집과 익명화

`prepare [옵션]`을 실행한다. 스크립트가 한 번에 다음을 한다.

- **수집.** 프로필 신원과 일치하는 내 커밋만 모든 로컬 브랜치에서 모은다. 커서(브랜치별 마지막 처리 커밋) 이후만 보고, 이미 기록한 커밋은 뺀다. 같은 날 다시 실행하면 그날 기록에 들어간 커밋을 다시 합쳐 하나의 기록으로 만든다. 상한(최대 커밋·파일)을 넘으면 최신부터 담고 `evidence.complete=false`로 알린다.
- **최소 거르기.** 이유가 분명한 것만 뺀다. 병합 커밋, 봇 커밋, 서로 상쇄되는 되돌림 쌍, 제외 경로·범위 밖만 바꾼 커밋, 빈 커밋, 생성·잠금·외부 파일만 바꾼 커밋, 공백만·주석만 바꾼 커밋. 뺀 수는 이유별로 `counts.excluded`에 있다.
- **중요도(0–100).** 유형 가중치(기능·성능 40, 수정 30, 구조 개선 22, 테스트 18, 문서 10, 유지보수 6, 스타일 4) + 변경 규모(로그 척도, 최대 25) + 새 모듈 10·새 코드 6 + 담당 기능·핵심 경로 8 + 테스트 추가 7 + 측정값 10. 7건 이하면 모두, 넘으면 상위 5건(60점 이상이면 7건까지)을 자세히 쓰고 나머지는 `others`(유형별 건수)로 묶는다.
- **진행 정도.** 담당 기능마다 마일스톤, 내 커밋, 테스트, 미완 표시로 추정치를 낸다. 식은 [profile](references/profile.md) 끝에 있다. 작업 단위가 있으면 단위별로 묶는다.
- **익명화.** 경로는 기능 라벨이나 일반적인 한국어 영역 이름으로 바꾸고, 커밋 메시지에서 위 비공개 정보를 `‹비공개›`로 지운다. 저장소 안의 내부 이름(하이픈·밑줄·숫자가 든 폴더·파일 이름)도 지운다.

출력 JSON만 보고 기록을 쓴다. `empty`가 true면 기록하지 않고 "새로 기록할 내 커밋 없음"으로 보고한다. `evidence.complete`가 false면 기록은 쓰되 `근거·신뢰도`의 수집 범위 줄에 `[미확인] 일부만 수집`을 적고, Notion 동기화는 `승인 시 진행`으로 남긴다.

## 4. 기록 쓰기와 저장

이 스킬을 실행한 세션이 리더다. 리더는 2~3절(준비, 수집과 익명화)을 직접 하고, 본문 작성은 작성자 서브에이전트에게 맡긴 뒤, 게이트·저장·동기화를 다시 직접 한다.

1. **작성자에게 맡긴다.** 작성자에게 주는 것은 `prepare` 출력 JSON, [entry](references/entry.md) 경로, 사용자가 이번 대화에서 알려 준 사실(있으면)뿐이다. 프로젝트 경로, diff, state.json, `.run.json`은 넘기지 않는다. 작성자 정의는 플러그인의 `agents/clonamic-task-logger.md`다.

   | 호스트 | 작성자 |
   |---|---|
   | Claude Code | 플러그인 에이전트 `clonamic-task-log:clonamic-task-logger`(Sonnet) |
   | Codex | 일반 서브에이전트에 `agents/clonamic-task-logger.md` 본문을 지시문으로 주고 모델 `luna` |
   | Cursor, Grok | 플러그인 에이전트, 또는 일반 서브에이전트에 같은 본문. Sonnet 급 모델을 쓸 수 있으면 그 모델 |
   | 서브에이전트를 쓸 수 없음 | 리더가 같은 본문을 따라 차례로 직접 쓰고, 보고서에 "작성자 서브에이전트 없이 리더가 작성" 한 줄을 남긴다 |

2. **리더가 검토한다.** 받은 초안을 [entry](references/entry.md) 규칙과 대조한다. `한눈에 보기`가 맨 앞, `근거·신뢰도`가 맨 끝인지, 근거 없는 절과 지어낸 수치가 없는지, 수치 줄마다 증거 라벨이 있는지, `증거 지문`이 `evidence.fingerprint`와 같은지 본다.
3. **게이트.** 초안을 임시 파일(`log-part/.draft.md`)로 저장하고 `gate --entry <파일>`을 실행한다. 종료 코드 2면 `blocked` 목록을 작성자에게 돌려 그 줄만 고치게 한다(서브에이전트가 없으면 리더가 고친다). 게이트 판정을 눈대중으로 뒤집지 않는다. 세 번 고쳐도 막히면 멈추고 남은 항목을 보고한다.
4. `write --entry <파일>`로 저장한다. 게이트를 다시 거친 뒤 `log-part/<날짜>.md`의 해당 블록만 바꾸고(블록 밖에 사용자가 쓴 글은 그대로), state.json과 index.md를 갱신한다. 같은 근거와 같은 본문이면 `unchanged`로 아무것도 바꾸지 않는다. 지난 날짜의 기존 기록은 `--replace-past` 없이는 바꾸지 않는다.

## 5. Notion 동기화

[notion](references/notion.md)의 순서를 따른다. 핵심만 적으면:

- 작업로그 위치는 실행마다 한 번만 확정한다(state.json의 ID를 조회해 확인, 없으면 제목 검색).
- 날짜 페이지 후보가 0개면 만들고, 1개면 갱신하고, 2개 이상이면 멈추고 보고한다.
- 증거 지문과 본문이 같으면 쓰지 않는다. 지난 날짜 페이지는 명시적 요청 없이 덮어쓰지 않는다.
- 생성 응답이 끊기면 다시 만들지 않고 검색·조회로 찾는다.
- 쓴 뒤 다시 조회해 제목, 절 제목, 증거 지문을 확인하고 `notion-set`으로 ID를 적는다. 그다음 진행 현황 페이지를 갱신한다.
- Notion MCP가 없거나 실패하면 로컬 기록은 그대로 두고 보고서에 `승인 시 진행`으로 남긴다.

## 6. 포트폴리오 정리

1. `portfolio`로 전체 기록의 묶음 데이터(기간, 유형별 건수, 기능별 진행률, 측정값, 날짜별 핵심 성과)를 받는다.
2. notion-template의 "포트폴리오 요약 페이지" 형식으로 쓴다. 4절처럼 작성자에게 맡기면 묶음 데이터와 notion-template 경로만 넘긴다. 대표 성과는 기록에 있는 것 가운데 고르고, 측정값은 기록에 있던 것만 쓴다. 새 사실을 더하지 않는다.
3. `write-portfolio --entry <파일>`로 게이트를 거쳐 `log-part/portfolio.md`에 저장하고, Notion 작업로그 아래 `포트폴리오 요약` 페이지를 같은 0/1/2+ 규칙으로 만들거나 갱신한 뒤 `notion-set --kind portfolio`로 적는다. 이 페이지도 사용자 개인 영역 안에 둔다.

## 7. 보고

채팅에 한 번 보고한다. 파일로 만들지 않는다. 맨 위가 결론이고 나머지는 목록이다.

```text
## 핵심 요약
- 기록 완료 — 2026-10-05, 반영 커밋 5건(제외 2건: 병합 1, 주석만 1)
- 미검증·실패: 없음

## 결과
- 로컬 기록 — log-part/2026-10-05.md 작성(같은 날 기록에 합침)
- Notion — 작업로그 / 2026-10-05 갱신, 제목·절·증거 지문 확인
- 진행 정도 — 결제 모듈 55%(추정, 지난 기록 대비 +10%p)

## 범위 밖 — 있을 때만
- 승인 시 진행1: Notion 동기화 — Notion MCP 도구가 없어 로컬에만 기록함
```

- 해당 없는 절과 줄은 뺀다. 기록 본문을 보고서에 다시 붙이지 않는다. 사용자가 보여 달라고 하면 그때 보여 준다.
- 보고서 안의 경로는 log-part 안의 기록 파일만 쓴다. 프로젝트 파일 경로는 쓰지 않는다.
