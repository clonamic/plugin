# Notion 페이지 템플릿

첫 실행 때 `log-part/notion-template.md`로 복사해 쓴다. 사용자가 사본을 고치면 사본을 따른다. 본문은 Notion 마크다운으로 보낸다. `{…}`는 쓸 때 채우는 자리이고, 채우지 못한 줄은 지운다.

## 작업로그 페이지

제목: `작업로그`

```text
> {프로젝트명} 프로젝트에서 제가 한 일을 날짜별로 기록합니다. 기록은 git 커밋을 근거로 자동 정리하며, 파일 이름이나 내부 식별자는 남기지 않습니다.

- 진행 현황 — 기능별 진행 정도(추정)
- 포트폴리오 요약 — 대표 성과와 측정된 효과
- 날짜 기록 — 아래 하위 페이지
```

## 날짜 기록 페이지

제목: `{notion_title}` (예: `2026-10-05`, 기간 정리는 `2026-09-28~2026-10-04`)

본문: 게이트를 통과한 로컬 기록 본문을 그대로 쓴다(맨 위 `# 제목` 줄만 뺀다). 맨 위에 한 줄 인용을 붙인다.

```text
> {파트} · {프로젝트명} · 근거 수준 A(git 저자 일치 커밋)

{로컬 기록 본문: 한눈에 보기 … 근거·신뢰도}
```

## 진행 현황 페이지

제목: `진행 현황`

```text
> 진행 정도는 마일스톤, 내 커밋, 테스트, 미완 표시를 근거로 한 추정입니다. 갱신 {날짜}

| 기능 | 진행 | 근거 | 갱신 |
|---|---|---|---|
| {기능} | {pct}% | {basis} | {날짜} |

## 작업 단위
- {작업 단위 이름} — {시작}~{끝}, 기능 평균 {pct}% (추정), 기간 경과 {time_pct}%
```

## 포트폴리오 요약 페이지

제목: `포트폴리오 요약`

```text
## 한눈에 보기
- 프로젝트 — {프로젝트명}
- 파트 — {파트}
- 기간 — {첫 기록}~{마지막 기록}, 기록 {n}일 [측정]
- 대표 성과 — 가장 중요한 성과 한 줄 [판단]

## 대표 성과
### {성과 이름}
- 문제 — 왜 필요했는지
- 한 일 — 내가 한 일과 방법
- 결과 — 확인된 결과 [측정] 또는 [판단]

## 담당 기능
- {기능} — {pct}% [판단] 추정, 맡은 범위 한 줄

## 측정된 효과
- [측정] {전}→{후} {단위} ({change_pct}%), {날짜}

## 기술 역량
- 기록에서 드러난 기술과 방식(근거가 된 기능을 함께) [판단]

## 기간별 기록
- {날짜} — {핵심 성과 한 줄}
```
