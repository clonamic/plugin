# Notion 페이지 템플릿

첫 실행 때 `log-part/notion-template.md`로 복사해 쓴다. 사용자가 사본을 고치면 사본을 따른다. 본문은 Notion 마크다운으로 보낸다. `{…}`는 쓸 때 채우는 자리이고, 채우지 못한 줄은 지운다. 메타데이터(지문, 해시, 수집 범위)와 HTML 주석은 어떤 페이지에도 넣지 않는다.

## 작업로그 페이지

제목: `작업로그`

```text
{프로젝트명}에서 제가 한 일을 날짜별로 기록합니다.

- 진행 현황 — 기능별 진행 정도
- 포트폴리오 요약 — 대표 성과와 기능별 기여
- 날짜 기록 — 아래 하위 페이지
```

## 날짜 기록 페이지

제목: `{YYYY-MM-DD}` (기간은 `MMDD~MMDD`, 예: `0928~1002`). 날짜만 쓴다.

본문은 게이트를 통과한 로컬 기록과 같은 구조다.

- 첫 블록은 대표 성과 한 줄이다. 로컬 기록의 제목 줄에서 날짜를 뺀 `{대표 성과}`를 그대로 쓴다.
- 이어서 로컬 기록의 `## 핵심 요약`부터 `## 포트폴리오 문장`까지를 그대로 쓴다. 절 제목과 순서를 바꾸지 않는다.
- 로컬 기록의 `# …` 제목 줄은 Notion 제목과 겹치므로 본문에 넣지 않는다.

```text
{대표 성과}

## 핵심 요약
…
## 한 일
…
## 포트폴리오 문장
…
```

## 진행 현황 페이지

제목: `진행 현황`

```text
갱신 {YYYY-MM-DD}

| 기능 | 진행률 | 최근 변화 | 남은 일 |
|---|---|---|---|
| {기능} | 약 {pct}% | {최근 변화} | {남은 일} |
```

- 진행률은 `status`의 `features` 값을 그대로 옮긴다. 최근 변화는 가장 최근 날짜 기록의 진행 상황 표에서 가져온다.
- 작업 단위(스프린트 등)가 있으면 표 아래에 `## 작업 단위` 절을 두고 `{이름} — {시작}~{끝}, 기능 평균 약 {pct}%` 한 줄씩 쓴다.
- 실행마다 표를 통째로 바꿔 쓴다.

## 포트폴리오 요약 페이지

제목: `포트폴리오 요약`. 구조와 쓰는 법은 [portfolio](portfolio.md)에 있다. 아래는 뼈대다.

```text
{역할 한 줄}

## 대표 성과
- {성과 문장}

## 기능별 기여
### {기능}
{맡은 범위와 기여 2~3문장}

## 사용 기술
- {기술} — {쓴 곳}

## 문제 해결 사례
### {사례 제목}
- 문제 — …
- 원인 — …
- 해결 — …
- 확인 — …
```
