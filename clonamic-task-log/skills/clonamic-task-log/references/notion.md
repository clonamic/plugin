# notion.md 서식과 Notion 동기화

## notion.md 서식

`log-part/notion.md`는 이 프로젝트의 기록이 Notion 어디에 있고 어떻게 나뉘는지 적는 파일이다. 프로젝트마다 따로 있다. 이 파일은 로컬 파일이고, Notion 페이지에는 메타데이터도 HTML 주석도 넣지 않는다.

```text
# Notion 위치

- 경로: 개인페이지 / project / demo / 작업로그
- 루트 페이지: 개인페이지
- 템플릿: notion-template.md

## 페이지

| 역할 | 제목 | ID | URL |
|---|---|---|---|
| 루트 | 개인페이지 | (워크스페이스 개인 영역) | |
| 프로젝트 모음 | project | 0a1b… | https://www.notion.so/… |
| 프로젝트 | demo | 1a2b… | https://www.notion.so/… |
| 작업로그 | 작업로그 | 3c4d… | https://www.notion.so/… |
| 진행 현황 | 진행 현황 | 5e6f… | https://www.notion.so/… |
| 포트폴리오 요약 | 포트폴리오 요약 | (포트폴리오 정리 때 생성) | |

## 구조

작업로그
├── 진행 현황        기능별 진행(마일스톤이 있는 기능만 %)·최근 변화·남은 일, 실행마다 갱신
├── 포트폴리오 요약   `포트폴리오 정리` 때 만들고 갱신
├── 2026-10-05       날짜 기록(제목은 날짜만)
└── 0928~1002        기간 기록(제목은 MMDD~MMDD)
```

- 기본 위치는 `개인페이지 / project / <프로젝트> / 작업로그`다. `개인페이지`는 워크스페이스의 개인(Private) 영역 맨 위, `project`는 그 아래의 프로젝트 모음 페이지, 그 아래에 프로젝트마다 페이지를 둔다. 제목이 정확히 `개인페이지`(또는 사용자가 정한 루트)인 페이지가 하나 있으면 그 아래를 쓰고, `project`도 같은 0/1/2+ 규칙으로 찾거나 만든다(`notion-set --kind container`).
- state.json의 `notion` 값이 기준이고 notion.md 표는 사람이 보는 사본이다. 둘이 다르면 state.json을 따르고 notion.md를 고친다.

## 위치 확정 (실행마다 한 번)

1. state.json에 작업로그 ID가 있으면 조회(fetch)해 제목이 `작업로그`이고 부모가 프로젝트 페이지인지 확인한다. 맞으면 끝.
2. 없거나 맞지 않으면 위에서부터 찾는다. 각 단계에서 정확히 같은 제목 후보를 센다.
   - 0개: 만든다(첫 실행이거나 사용자가 위치를 정한 경우).
   - 1개: 그 페이지를 쓴다.
   - 2개 이상: 멈추고 후보를 사용자에게 보여 고르게 한다. 임의로 고르지 않는다.
3. 확정한 ID를 `notion-set`으로 적는다. 한 실행 안에서 다시 찾지 않는다.

## 날짜 페이지 동기화

1. 제목은 `prepare` 결과의 `notion_title`이다. 하루는 `YYYY-MM-DD`, 기간은 `MMDD~MMDD`(예: `0928~1002`)다.
2. state.json `notion.days[날짜]`에 ID가 있으면 조회해 제목을 확인한다. 없으면 작업로그 아래에서 같은 제목을 찾는다.
   - 0개: notion-template의 "날짜 기록 페이지"로 만든다.
   - 1개: 그 페이지를 갱신한다.
   - 2개 이상: 멈추고 보고한다.
3. 본문은 로컬 기록과 같은 구조다. 첫 블록은 대표 성과 한 줄, 이어서 로컬 기록의 `핵심 요약`부터 마지막 절까지다. 갱신 전에 페이지 본문을 읽어 이번 기록과 같으면 쓰지 않는다. 같은 날짜를 다시 실행하면 같은 페이지를 갱신한다.
4. 명시적으로 요청한 날짜는 추가 플래그 없이 쓴다. 요청하지 않은 지난 날짜 페이지는 덮어쓰지 않는다.
5. 생성 요청 뒤 응답이 끊겼으면 다시 만들지 않는다. 같은 제목을 검색·조회해 생긴 페이지를 찾고 그 페이지로 이어 간다.
6. 쓴 뒤 다시 조회해 제목, 첫 블록, 로컬 기록에 있는 절 제목이 모두 일치하는지 확인한다. 다르면 한 번 고쳐 쓰고, 그래도 다르면 보고서에 실패로 적는다.
7. `notion-set --kind day --date <날짜> --id <ID> --url <URL> --title <제목>`으로 적는다.

## 진행 현황 페이지

날짜 페이지를 쓴 뒤 `tasklog.py status`의 `features`와 가장 최근 기록의 `오늘 변화`로 표를 통째로 바꿔 쓴다(프로젝트 전체 기능이 들어간다. 날짜 기록에는 그날 손댄 기능의 한 줄만 있다). 열은 기능 · 진행 · 최근 변화 · 남은 일이고, 맨 위에 갱신일을 적는다. 퍼센트는 마일스톤이 있는 기능만 쓰고 나머지는 `마일스톤 미설정`이다. 경로가 사라진 기능은 표에서 뺀다. 빈 칸을 `-`로 채우지 않는다. 서식은 [notion-template](notion-template.md)의 "진행 현황 페이지"다.

## 포트폴리오 요약 페이지

`포트폴리오 정리` 때만 만들고 갱신한다. 같은 0/1/2+ 규칙을 쓰고 `notion-set --kind portfolio`로 적는다. 구조와 쓰는 법은 [portfolio](portfolio.md)다.

## 규칙

- Notion에는 로컬 기록과 같은 본문만 쓴다. 게이트를 통과하지 않은 글은 보내지 않는다.
- 어떤 페이지에도 지문, 해시, 수집 범위 같은 메타데이터와 HTML 주석을 넣지 않는다.
- Notion MCP 도구(검색, 조회, 페이지 생성, 페이지 수정)만 쓴다. 직접 API 호출, API 키, 브라우저 조작으로 우회하지 않는다.
- 페이지를 지우거나 옮기지 않는다. Notion MCP에는 휴지통 기능이 없다. `tasklog.py forget`이 출력한 페이지 id·url을 사용자에게 알려 직접 삭제하게 한다(사용자 조치).
